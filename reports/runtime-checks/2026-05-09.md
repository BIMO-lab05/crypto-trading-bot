## Recommendations

Ordered by impact. Anchored to evidence above.

### 1. Wrong now (today)

1. **Fix `EMERGENCY_STOP` mount** (carry-over from 2026-05-08). On host:
   ```
   docker compose -f docker-compose.unified.yml stop trading-engine api-gateway
   rmdir EMERGENCY_STOP && touch EMERGENCY_STOP
   docker compose -f docker-compose.unified.yml up -d --force-recreate trading-engine api-gateway
   ```
   Until this is done, file-based kill switch remains non-functional. The detection code increments a Prometheus counter (`risk_limit_breaches_total{breach_type="emergency_stop_mount_broken"}`) but does **not** halt trading.

2. **Decide on `MAX_DAILY_LOSS_PCT` drift.** Either:
   - (a) restore `MAX_DAILY_LOSS_PCT=5.0` in `services/trading-engine/.env:108` to match CLAUDE.md "5% daily-loss circuit-breaker (always)" rule, OR
   - (b) file an ADR documenting the 10.0% bump (parallel to ADR-010 for `max_risk_per_trade`) and update CLAUDE.md project-rules line.
   The current state — silently doubled cap, no ADR — bypasses a load-bearing rule and will not survive `/wiki-lint`.

3. **Remove dead env vars from repo-root `.env`** to prevent operator misconception:
   - Line 111 `MAX_DAILY_LOSS=0.10` — env var name doesn't match pydantic field (`max_daily_loss_pct` ← `MAX_DAILY_LOSS_PCT`). Line is ignored.
   - Line 306 `ENABLE_AUTOMATIC_TRADING=true` — no consumer in `services/`. Misleading; real flag is `AUTO_TRADING_ENABLED` in service-local `.env`.
   - Service-local `services/trading-engine/.env:127 MAX_RISK_MULTIPLIER=2.0` — also dead. Code uses `ensemble_confidence_size_multiplier` (default 3.7).

4. **Confirm stack state from host.** This audit infers "likely down" from log-file timestamps. Operator should run `docker compose -f docker-compose.unified.yml ps` and either bring stack up if down or paste output into next audit so verdict has runtime grounding.

### 2. Missing

1. **Pre-live LIVE-mode validator** (carry-over). When `TRADING_MODE=LIVE`, refuse boot unless `max_risk_per_trade ≤ 0.02` AND `LIVE_TRADING_ACK=I_UNDERSTAND_REAL_MONEY`. ADR-010 says "Implemented separately if/when LIVE is enabled" — still TODO. Without it, flipping LIVE inherits paper's 10% cap silently.

2. **Notification on broken kill-switch.** `risk_limit_breaches_total{breach_type="emergency_stop_mount_broken"}` increments but no Telegram/email alert is wired to it. Operator has no way to know in real time. Add an alert rule in Prometheus + notification-service handler.

3. **On-disk P&L snapshot artifact.** This scheduled audit cannot reach `localhost:8000`. To make daily reports useful, `portfolio-manager` should write `services/portfolio-manager/logs/snapshot.json` every N minutes containing equity, open positions, realized P&L last 50 trades, win-rate, max drawdown 30d. Audit reads file. Without this, every sandbox-run audit produces the same "could not retrieve" verdict.

4. **Startup-time assertion that logs loaded risk caps and warns on drift.** On boot, trading-engine should log `LOADED_RISK_CAPS: max_risk_per_trade={x}, max_daily_loss_pct={y}` and emit a warning if either differs from documented defaults without an ADR pointer in env. Catches silent drift like today's `MAX_DAILY_LOSS_PCT=10.0`.

### 3. Improve

1. **Move scheduled audit to host context.** This audit and yesterday's reach the same 90% of conclusions because both run sandboxed. Either run audit via a host-side cron that has Docker access, or surface the necessary state via files (recommendation 2.3) so the sandbox-side audit becomes useful.

2. **Diff this report against yesterday in next audit.** Compare 2026-05-09 against 2026-05-08; flag findings that **persisted** (EMERGENCY_STOP directory, `MAX_DAILY_LOSS_PCT` drift, dead env vars) versus findings that were **fixed**. Right now audit re-discovers static drift each day with no continuity signal.

3. **Phase 03 tournament-harness work is not affecting trading-engine runtime today.** No regress concern for current audit. When `tournament-harness` ships, audit checklist needs an entry for that service's health probe + queue lag.
