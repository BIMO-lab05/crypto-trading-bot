## Task 2 — The phase's code is inside the running containers

### 2.1 Method

Every gate below greps for an **identifier**, never for prose. The Edit/Write
format hook rewraps comments at 88 columns, so a sentence that exists on the host
can be line-broken in a way that defeats a phrase grep; identifiers survive
reflow.

Presence and absence are asserted **separately**, each on its own labelled line,
never chained with `&&` — a chained gate reports one verdict for two dozen
independent facts and goes red on a correct deploy.

The exit-code inversion is handled explicitly. `grep` exits 1 when it finds
nothing, so a PRESENCE proof succeeds on rc 0 and an ABSENCE proof succeeds
**only** on rc 1. **Any other rc (2 = file missing, unreadable, or bad pattern) is
recorded as an ERROR, not an absence** — otherwise a single mistyped in-container
path would "prove" that every literal in the phase is gone. The prover
implements this as:

```bash
abst() {
  docker exec "$1" grep -Eq -- "$3" "$2"; rc=$?
  if   [ "$rc" = 1 ]; then echo "ABSENT ok     ..."
  elif [ "$rc" = 0 ]; then echo "ABSENT FAIL   ..."; fail=1
  else echo "ABSENT ERROR  rc=$rc -- file missing or grep failed; this is NOT proof of absence ..."; fail=1
  fi
}
```

Absence checks are aimed at **the file that actually held the literal**:
`equity=10000` lived in `risk/dynamic_risk_budget.py` and
`trading_enhancements/portfolio_heat.py`, never in `handlers/signals.py`; the
fixed-0.7 confidence form is the one that lived in `handlers/signals.py`. For
item C the checks use plan 22.1-04's **declaration-form** regexes, not the bare
`adx_period` token — that plan deliberately left rationale comments containing
the token, so a bare-token absence check would have failed on a correct deploy.

**A recursive absence check cannot do item F's job on its own.**
`grep -rEq 'equity=10000' /app/app` returns rc 1 both when the literal is gone
*and* when the file that held it was never in the image at all — the ERROR branch
only fires if `/app/app` itself vanished. That is the same "a missing path proves
every literal gone" hole this section exists to close, one level up. Item F
therefore asserts the two **per-file** rows the plan's own `<verify>` block names
individually, and keeps the recursive sweep as a superset check in the other
direction (no *other* file grew the literal). The two files are confirmed present
in the image in §2.3, so neither per-file gate is vacuous.
