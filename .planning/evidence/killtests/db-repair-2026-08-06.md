# TimescaleDB klines hole repair — 2026-08-06

## What

`market_data.klines` had collection-downtime holes (worst: 15m missing
2026-05-22 → 2026-07-27 and 2026-08-01 19:00 → 2026-08-02 12:15; 240m missing
2026-05-22 → 2026-06-25; smaller 60m/D holes). Consequence: live TA computed
deep-window indicators across the cliffs — e.g. the 200-EMA trend filter at
240m×300 bars returned spread 1.55% / confidence 0.31 where contiguous data
gives 6.35% / 1.00 (ADAUSDT, measured 2026-08-06). This also made the
killtests golden-parity gate unpassable: the offline leg reads contiguous
Bybit history (backfill CSVs), the live leg read the gapped DB.

## How

Missing bars inserted from the validated 365d backfill CSVs
(`backtesting/data/*_{15,60,240,1440}m_365d_bybit.csv` — fresh Bybit mainnet
fetch of 2026-08-06 ~14:05 UTC, `is_mainnet` asserted per row, forming bars
dropped by the fetcher). Staged via temp table, then
`INSERT ... ON CONFLICT ("timestamp", symbol, "interval") DO NOTHING` —
existing rows never modified. User approved 2026-08-06 before execution.

- Staged: 231,755 rows (5 symbols × 4 intervals × 365d)
- Inserted (was missing): **174,776** — per symbol ≈ 31.9k×15m, 1.42k×60m,
  1.58k×240m, 62×D
- Already present (untouched): 56,979

## Reversibility

Every inserted row carries the exact marker `created_at = 1786026362487`.
Full revert:

```sql
DELETE FROM klines WHERE created_at = 1786026362487;
```

## Verification

Post-repair, `/api/v1/klines/{sym}` at limit=400 shows 0 irregular steps for
BTC/SOL/ADA × {15,60,240}; golden-parity endpoint sweep no longer diverges on
deep-window endpoints (the pre-repair ADA 240m trend DIFF was the only one).

## Note

This was an operator data repair, not part of the killtests harness (spec §9
"no changes to prod databases" refers to what the harness itself does; the
harness only ever reads). The mainnet-pollution rule (2026-04-25) concerns
testnet rows our DB collected — these inserts are fresh mainnet history.
