## RES-01 repair (executed 2026-08-16, operator-approved)

Script: `scripts/repair_res01_trades_pnl.sql`, single transaction, hard postcondition asserts.
Backup: full `trades` copy in `trades_backup_res01` (43 rows); revert SQL in the script header.
Provenance: every touched row carries `metadata.res01_corrected` (+ `res01_prev_pnl`, and
`res01_prev_quantity`/`res01_prev_total_value` on trade 93).

Convention of record (reverse-engineered from every position opened ≥ 2026-08-06, verified to
1e-8 by hand on positions 61 and 64): exit trade `realized_pnl` = gross leg P&L −
`entry_fee × exited_qty / original_qty` − exit trade fee; entry trades NULL.

What was wrong and what changed:

- **Group A** (positions 46–56, one full exit each, 11 rows): exit rows stored GROSS — drift
  per position equaled `entry_fee + exit_fee` exactly. Set exit row = position net.
- **Group B** (positions 57/59/60, partial-exit era, 7 exit rows recomputed): earliest partial
  exits stored gross, later ones already net (mixed regime). Recomputed all from first
  principles in SQL; residual snap turned out unnecessary — recomputation landed exact.
- **Trade 93** (pos 59 final close): carried the phantom FULL quantity 1.08043760 (H5 bug)
  instead of the remaining 0.48500844 — the source of the +1.90 headline drift and ~0.595 SOL
  of phantom volume. Quantity + total_value corrected; its fee left as recorded (computed on
  phantom qty; `positions.exit_fee` includes it, so the ledger identity requires keeping it —
  documented residue, ~$0.044 of fee charged on quantity never actually traded).

Verification (all pasted from live DB):
- Per-position drift after repair: **0 rows** across all 19 closed positions (exact equality,
  not tolerance).
- Global identity: `sum(trades.realized_pnl)` = `sum(positions.realized_pnl)` closed =
  `portfolios.realized_pnl` = **0.37103039**.
- `sum(trades.fee)` unchanged: 2.05495742.
- Downstream: `/api/portfolio/performance` via gateway serves `total_return 0.37103039` live.

Side observation (pre-existing, NOT this repair): `/api/portfolio/trades` queries
`portfolio_id='default'` and returns an empty set while data lives under `paper_trading` —
reporting quirk, filed as RES-08.
