<critical_findings>
Read these before touching code. Both were verified against the live tree on 2026-08-16 and both contradict parts of the original RES-08 write-up.

**FINDING 1 — the seed-key change is mandatory, not optional scope.**
`app/services/portfolio_manager.py:54-63` (`_create_default_portfolio`) seeds `self.portfolios["default"]` and `self.transaction_history["default"]` at construction. `get_portfolio()` (`:76-78`) is a strict `dict.get`. If endpoints resolve to `paper_trading` while the seed stays keyed `"default"`, every PM portfolio endpoint regresses **from 200-empty to 404** — `handlers/transaction_history.py:52-54` raises it explicitly, and `sync_with_trading_engine` (`:171-173`) bails the same way. The seed key and `scheduler/performance_snapshot.py:339` (`return ["default"]`) MUST move to `settings.default_portfolio_id` in the same commit. Do not let a reviewer strip this as unrelated.

**FINDING 2 — this fix does NOT make the 43 trades appear. Do not chase that outcome.**
portfolio-manager never reads the `trades` table — grep confirms no `FROM trades` anywhere in `app/`. `self.transaction_history` is in-memory, written only by `_record_transaction`, which is reachable only through manual buy/sell, which is itself gated off by FIX 11 (`MANUAL_TRANSACTIONS_DISABLED_DETAIL`, `handlers/transactions.py:21-28`).

Post-fix, `GET /api/portfolio/trades` returns:
`{"portfolio_id":"paper_trading","transactions":[],"total_count":0}`

That is the **correct and expected** result of this plan. The observable delta is `portfolio_id` flipping from `default` to `paper_trading` while the status stays **200, not 404**. PM being unhydrated from the `trades` table is a separate defect — file it, do not absorb it here.

**FINDING 3 — `get_settings()` does not exist in either service.**
Both use a module-level `from app.config import settings` (gateway `main.py:51`, PM `main.py:33`). Use that. Read `settings.default_portfolio_id` **inside the function body**, never as a signature default — FastAPI evaluates signature defaults once at import, which freezes the value and violates `.claude/rules/money.md`. Body reads also keep `monkeypatch.setattr` working in tests. Do not add a `get_settings()` accessor.

**Out of scope (locked):** do not touch trading-engine; do not rename the DB row; do not alias `"default"` to `paper_trading` in any lookup — an explicitly-requested nonexistent portfolio must still 404.
</critical_findings>

<resolution_rule>
One resolution point per service. Apply mechanically:

- **HTTP endpoint bodies only** (`app/main.py` in each service): signature becomes `Optional[str] = None` (or `Query(None)` where `Query` was used), and the first line of the body is
  `portfolio_id = portfolio_id or settings.default_portfolio_id`
- **Everything downstream** (`app/handlers/*.py`, `app/services/portfolio_manager.py`): **drop the default entirely — make `portfolio_id` a required parameter.** Every one of these is already called with an explicit positional value from its `main.py` wrapper, and the `Query(...)` defaults sitting in handler signatures are vestigial (FastAPI never evaluates them; these are plain function calls).

Signature ordering was verified: every downstream `portfolio_id` is either the first parameter or sits immediately after `request: Request` (which has no default), so promoting it to required is syntactically safe in all 14 downstream sites. If you nonetheless hit a required-after-defaulted `SyntaxError`, fall back to `Optional[str] = None` + a body resolve in that one function rather than reordering the signature.

**Empty-string note.** `portfolio_id or settings.default_portfolio_id` also swallows `""`, so `?portfolio_id=` resolves to the default rather than 404ing. That is the intended reading of constraint 4 here (an empty param is an absent param). If a reviewer wants it strict, `if portfolio_id is None` is the one-token change — but pick one and keep both services consistent.

**Docstrings count.** 15 sites carry `Portfolio identifier (default: "default")`. They are inside triple quotes, so no comment filter exempts them — the gate is literally zero occurrences. Rewrite them as `Portfolio identifier (defaults to settings.default_portfolio_id)`.
</resolution_rule>
