<objective>
Close the JWT default-secret hole identified in `.planning/codebase/CONCERNS.md:26-31`. Today, api-gateway boots with the known fallback secret `_DEV_ONLY_SECRET` whenever `ENVIRONMENT != production|staging`, even if the operator is running `TRADING_MODE=LIVE` or `PAPER_TRADING_MODE=false`. All issued tokens are then forgeable by anyone who knows the literal fallback string (it is checked into the public repo at `auth_models.py:49`). The Pydantic `Settings.jwt_secret_key` field also still carries `default="your-secret-key-change-in-production"` — a second known-insecure literal in a separate code path.

Purpose: extend hard-fail to mode-driven LIVE/non-paper boots, and eliminate the dead Pydantic field so only one JWT-secret code path remains. This is a security fix — token forgery risk in any non-prod environment that has been flipped toward real-money trading.

Output:
- `auth_models._validate_jwt_secret()` extended to additionally hard-fail on `TRADING_MODE=LIVE` or `PAPER_TRADING_MODE=false`, regardless of ENVIRONMENT.
- `config.Settings.jwt_secret_key` field removed entirely (it has zero consumers in `app/` — verified via grep — and only existed as a dead second code path with an insecure default).
- Unit tests covering all 5 scenarios from scope; existing `auth_models` and `config` tests stay green.
- Tests pass inside the running `crypto-bot-api-gateway` container (fastapi 0.109 pin; host-pip 0.136 must NOT be used per CLAUDE.md).
</objective>
