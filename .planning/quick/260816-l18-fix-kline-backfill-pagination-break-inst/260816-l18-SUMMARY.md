# Quick Task 260816-l18 Summary

Three independent live-diagnosed defects fixed: kline backfill truncating to one
batch, `InstrumentsCache` silently missing SOLUSDT behind the connector's 500-item
page-1 cap, and the MLGATE marker writing to a root-owned tmpfs the app cannot use.

## What changed

### Task 1 — kline pagination (`9926954`)

`get_kline` drops the still-forming candle by time filter, so a *full* page returns
999 rows against a `MAX_CANDLES_PER_REQUEST` of 1000. `get_historical_klines` read
that short batch as "history exhausted" and broke — a 5-day 1m backfill stored 999
bars instead of ~7,200.

Removed the `len(klines) < MAX_CANDLES_PER_REQUEST -> break` (4 lines), replaced
with a comment naming the three surviving termination conditions so the deletion is
not re-litigated:

- empty batch → `break`
- `oldest_ts <= target_start_ms` → `break`
- `batch_count < max_batches` loop guard

plus `current_end_ms = oldest_ts - 1` strictly decreasing every iteration, because
`oldest_ts <= current_end_ms` always holds. Cost: exactly one extra API call when
history genuinely runs out.

New standalone test module `tests/test_fetcher_pagination.py` (3 tests). It had to
be standalone: `test_fetcher.py` and `test_fetcher_enhanced.py` both carry a
module-level `pytestmark = pytest.mark.skip` from the PR #86 fix-up, so the
pagination loop had **zero** live coverage and anything added there would have
silently skipped — a false green.

### Task 2 — InstrumentsCache per-symbol fallback (`1c85781`)

`refresh()` made a single bulk `_fetch(symbol=None)`. bybit-connector does not
paginate Bybit's instruments-info, so the response is capped at page 1 (500 items)
and SOLUSDT is not on it. The engine logged `refreshed 4/5 symbols` and SOL traded
with the min-notional gate **failed open**.

Added a per-symbol fallback pass after the bulk loop. Design points, all deliberate:

- `try/except (httpx.HTTPError, ValueError)` sits **inside** the loop — one
  unlisted or erroring symbol must not abort the remaining fallbacks, or the
  documented fail-open contract breaks. `refresh()` still never raises.
- The missing list is built from `dict.fromkeys(symbols)` (caller order,
  de-duplicated), not from the `wanted` set — set iteration order is
  nondeterministic and the new tests assert call ordering.
- Bounded at `len(symbols)` extra calls. No retries, no backoff, no concurrency;
  a comment says so.
- The summary log now counts real cache coverage (`len(wanted & self._cache.keys())`)
  after both passes. The old incrementing counter would still have said 4/5 after
  the fallback filled SOL.

A cache entry already present but TTL-stale is skipped by the fallback. That is
correct — `get()` owns TTL refetch; `refresh()` deliberately stays TTL-unaware.

### Task 3 — MLGATE marker path (`e57a811`)

`_MLGATE_MARKER_PATH` was `/run/mlgate_auto_flip.json`. `/run` is a root-owned
tmpfs in the container and the app runs as uid 1000, so the best-effort marker
write in `app/lifespan/ml.py` raised `PermissionError` on every boot. The warning
survived `--force-recreate`, ruling out the WSL bind-mount race. Moved to `/tmp`
(mode 1777, always writable); the marker is container-local cross-process state
regenerated each boot, so tmpfs loss on recreate is acceptable.

`app/lifespan/ml.py` needed no edit — it from-imports the constant, so the new
value flows through at import time.

The literal was duplicated in the e2e harness and moved in the same commit:
seeding `/run` while the app reads `/tmp` would have silently turned
`dsr_evidence` from PASS to UNKNOWN. `RUNBOOK.md:385` updated too. No `/run/mlgate`
literal survives outside `.planning/`.
