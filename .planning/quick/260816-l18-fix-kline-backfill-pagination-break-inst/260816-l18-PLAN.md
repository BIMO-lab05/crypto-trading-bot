## Task 1 — market-data: pagination stops after one batch

**Problem (verified live).** `get_kline` drops the still-forming candle by time filter
(`fetcher.py:200-205`), so the first paginated batch returns **999** rows while
`MAX_CANDLES_PER_REQUEST` is 1000. `get_historical_klines` reads that short batch as
"history exhausted" and breaks:

`services/market-data-service/app/fetcher.py:371-374` —
`if len(klines) < MAX_CANDLES_PER_REQUEST: ... break` ("Received partial batch, no more data").

Empirically `POST /api/v1/collect/kline/BTCUSDT?interval=1&days=5` stored **999** klines
instead of ~7,200.

**Files / actions.**

1. `services/market-data-service/app/fetcher.py` — **delete lines 371-374** (the comment
   `# Check if we got fewer candles than requested (no more data available)`, the `if`, its
   `logger.info`, and the `break`). Delete nothing else in the loop.

   Termination remains guaranteed by three surviving conditions — state this in the commit
   body so nobody re-litigates the deletion:
   - empty batch → `break` (`:348-350`),
   - `oldest_ts <= target_start_ms` → `break` (`:367-369`),
   - `batch_count < max_batches` loop guard (`:335`),
   - and `current_end_ms = oldest_ts - 1` (`:377`) **strictly decreases** every iteration
     because `oldest_ts <= current_end_ms` always holds.

   Cost of the fix: exactly one extra API call when history genuinely runs out.

2. `services/market-data-service/tests/test_fetcher_pagination.py` — **new file.**

   **Do not put the test in `test_fetcher_enhanced.py` or `test_fetcher.py`.** Both carry a
   module-level `pytestmark = pytest.mark.skip(reason="stale tests after PR #86 refactor…")`
   (line 15 of each), so all four existing `get_historical_klines` tests are skipped and any
   test added there would silently skip — a false green. The pagination loop currently has
   **zero live coverage**. The new file must have no `pytestmark` skip.

   `pytest.ini` sets `asyncio_mode = auto`, so plain `async def test_…` works with no
   decorator.

**Behavior (write these tests first, watch the first one fail, then delete lines 371-374).**

- `test_short_batch_does_not_stop_pagination` — the regression test.
  - Build the window explicitly: `end_time = datetime.utcnow()`, `days=5`, `interval="1"`
    (1-minute bars → `expected_candles` ≈ 7200 → `max_batches` = 17, so the cap is not what
    stops the loop).
  - Compute fake timestamps from **`end_ms = int(end_time.timestamp() * 1000)`** — the same
    expression `get_historical_klines` uses (`:316`). Do **not** use `time.time()`:
    `datetime.utcnow()` is naive and `.timestamp()` reads it as local time, so only the
    identical expression keeps the fake rows inside the window that the final filter at
    `:393-396` applies.
  - Batch 1 = **999** rows (limit − 1, i.e. the forming candle was dropped), newest at
    `end_ms - 60_000`, stepping back 60_000 ms per row. Its `oldest_ts` is ~999 minutes back
    — **strictly greater than `target_start_ms`** (7200 minutes back). This matters: if
    batch-1 timestamps reached the target, the `oldest_ts <= target_start_ms` break would
    fire and the test would pass on unfixed code.
  - Batch 2 = 999 more rows continuing downward from batch-1 `oldest_ts - 60_000`; still
    inside the window.
  - Batch 3 = `[]` (empty-batch break ends the loop).
  - Patch the method, not the HTTP layer:
    `patch.object(fetcher, "get_kline", new=AsyncMock(side_effect=[b1, b2, []]))`. This
    bypasses both `bybit_connector_retry` and the closed-candle filter, which would otherwise
    fight the mock.
  - Call with `rate_limit_delay=0` and the explicit `end_time` so the test neither sleeps nor
    drifts.
  - Assert **all three**: `fetcher.get_kline.await_count >= 2`; `len(result) == 1998`; and
    batch-2's oldest timestamp is present in `[k["timestamp"] for k in result]`.
- `test_reaching_target_start_still_breaks` — batch 1 returns rows whose `oldest_ts` is at or
  below `target_start_ms`; assert `await_count == 1`. Guards the deletion against runaway
  pagination.
- `test_empty_first_batch_returns_empty` — first call returns `[]`; assert `await_count == 1`
  and `result == []`.

Row dicts need `timestamp` plus the usual `open/high/low/close/volume` string fields; only
`timestamp` is load-bearing (dedupe at `:383-387` and the window filter keys on it).

Each test must end with `await fetcher.close()` (same as the skipped neighbours), or every run
emits httpx client-teardown warnings.

**Verify.**

```

cd services/market-data-service && python3 -m pytest tests/integration/test_collection_handlers.py --no-cov -q
```

**Done when.** New test file fails on unmodified `fetcher.py` (RED, observed), passes after the

## Task 2 — trading-engine: InstrumentsCache misses SOLUSDT

**Problem (verified live).** `refresh()` makes one bulk call `_fetch(symbol=None)`
(`instruments_cache.py:170`). bybit-connector does not paginate Bybit's instruments-info, so
the response is capped at exactly **500** items and SOLUSDT is not on page 1. The engine logs
`InstrumentsCache: refreshed 4/5 symbols` and SOL trades with the min-notional gate failed
open. The per-symbol path works — `GET /api/v1/market/instruments-info?category=linear&symbol=SOLUSDT`
returns the spec.

**Files / actions.**

1. `services/trading-engine/app/services/instruments_cache.py` — in `refresh()`, after the
   existing bulk `for raw in items:` loop (`:181-190`) and **before** the `logger.info`
   (`:192-197`), add a per-symbol fallback pass:

   - Compute the still-missing list preserving caller order and de-duplicated:
     `[s for s in dict.fromkeys(symbols) if s not in self._cache]`. **Do not iterate the
     `wanted` set** — set order is nondeterministic and the new tests assert call ordering.
   - For each missing symbol: `await self._fetch(symbol=sym)`, find the item whose `symbol`
     matches, `_parse_instrument` it, and store it in `self._cache` on success.
   - **The `try/except (httpx.HTTPError, ValueError)` goes *inside* the loop, per symbol**,
     logging a WARN and `continue`-ing. It must **not** be folded into the outer try at
     `:171`: one unlisted or erroring symbol must not abort the remaining fallbacks, or the
     documented fail-open contract breaks.
   - Bound: at most `len(symbols)` extra calls. **No retries, no backoff, no concurrency** —
     say so in a comment so nobody adds them later.
   - Leave the outer bulk-failure fail-open behaviour at `:171-177` exactly as is.

2. Same file — make the summary log truthful after the fallback. Replace the incrementing
   `loaded` counter with cache coverage computed after both passes:
   `len(wanted & self._cache.keys())`. Without this the log still says 4/5 after the fallback
   filled SOL.

   Existing tests stay green: `test_refresh_populates_cache` and
   `test_refresh_filters_to_requested_symbols` both have every wanted symbol in the bulk body,
   so no fallback fires and `cache._cache.keys() == {"BTCUSDT"}` still holds.

3. `services/trading-engine/tests/test_instruments_cache.py` — extend. Add a `_sol_item()`
   helper next to `_btc_item()` / `_eth_item()` (`:32-60`): symbol `SOLUSDT`, `minOrderQty`
   `"0.1"`, `qtyStep` `"0.1"`, `tickSize` `"0.010"`, `minNotionalValue` `"5"`. Reuse the
   existing `_payload()` and `CONNECTOR_URL`.

**Behavior (two new tests, both `@pytest.mark.asyncio` + `@respx.mock` like their neighbours).**

- `test_refresh_falls_back_to_per_symbol_when_bulk_omits_symbol`
  - **respx route order matters — respx matches in registration order.** Register the
    symbol-scoped route **first**:
    `respx.get(f"{CONNECTOR_URL}/api/v1/market/instruments-info", params={"symbol": "SOLUSDT"})`
    returning `_payload([_sol_item()])`; then register the catch-all bulk route returning
    `_payload([_btc_item(), _eth_item()])` (SOL absent — this is the 500-cap simulation).
    (Equivalent alternative: one route with a `side_effect` callable that inspects
    `request.url.params`. Pick one; do not mix.)
  - `await cache.refresh(["BTCUSDT", "ETHUSDT", "SOLUSDT"])`.
  - **Load-bearing assertions (cache state):** `cache._cache.keys() == {"BTCUSDT", "ETHUSDT",
    "SOLUSDT"}`; the SOL-scoped route was called exactly once; and
    `(await cache.get("SOLUSDT")).min_order_qty == Decimal("0.1")`.
- `test_refresh_fallback_error_does_not_abort_remaining_symbols`
  - Routes, in registration order: ETH-scoped → `httpx.Response(500)`; SOL-scoped →
    `_payload([_sol_item()])`; catch-all bulk → `_payload([_btc_item()])` (ETH and SOL both
    missing). A route keyed on `params={"symbol": …}` cannot match the bulk request, which
    sends only `category`.
  - `await cache.refresh(["BTCUSDT", "ETHUSDT", "SOLUSDT"])` must not raise.
  - **Load-bearing assertions (cache state):** `"SOLUSDT" in cache._cache` (the loop continued
    past the ETH failure) and `"ETHUSDT" not in cache._cache`. This is what proves the
    `try/except` sits inside the loop.

**Log assertion (secondary).** The `refreshed N/M` count change is worth asserting but is not
the load-bearing check — the orchestrator reads the real count from container logs in handoff
step 3. Use the idiom that already works in this suite (see
`tests/test_exposure_gate_all_paths.py:110-120` for a passing example):

wrap the `refresh()` call in `with caplog.at_level(logging.INFO, logger="app.services.instruments_cache"):`
and assert `any("refreshed 3/3" in rec.message for rec in caplog.records)` (respectively
`"refreshed 2/3"`). If caplog captures nothing, **do not weaken the cache-state assertions and
do not fight the logging config** — drop the log assertion and note it in the commit body.

## Task 3 — trading-engine: MLGATE marker path is unwritable

**Problem (verified live).** `_MLGATE_MARKER_PATH = "/run/mlgate_auto_flip.json"`
(`app/preflight/checks.py:46`). `/run` is a root-owned tmpfs in the container and the app runs
as uid 1000, so the best-effort marker write in `app/lifespan/ml.py:184-197` raises
`PermissionError` on every boot and logs `MLGATE marker write failed: PermissionError`. The
warning persists across a `--force-recreate`, so this is not the WSL bind-mount race.

Config-only change — no `tdd="true"`, no new behaviour test. The marker is container-local
cross-process state regenerated on every boot, so tmpfs loss on recreate is acceptable.

**Files / actions.**

1. `services/trading-engine/app/preflight/checks.py:46` — change the constant to
   `"/tmp/mlgate_auto_flip.json"`. Extend the comment above it (`:42-45`) with the reason:
   `/run` is root-owned tmpfs and the service runs as uid 1000; `/tmp` is mode-1777 and always
   writable; the marker is regenerated every boot so tmpfs loss is fine.

2. **Do not edit `app/lifespan/ml.py`.** It `from`-imports the constant at `:31`, so the new
   value flows through at import time. (Aside, pre-existing and out of scope: that from-import
   means `monkeypatch.setattr("app.preflight.checks._MLGATE_MARKER_PATH", …)` does not rebind
   ml.py's copy — the tests pass `marker_path=` explicitly instead. Leave it.)

3. **The literal is duplicated in the e2e harness — these must move in the same commit or the
   e2e smoke test breaks silently** (the fixture would seed `/run` while the app reads `/tmp`,
   turning `dsr_evidence` from PASS to UNKNOWN):
   - `tests/e2e/conftest.py:489` — the seeding exec. Replace
     `mkdir -p /run && echo '…' > /run/mlgate_auto_flip.json` with
     `echo '…' > /tmp/mlgate_auto_flip.json` (drop the now-pointless `mkdir`; `/tmp` always
     exists).
   - `tests/e2e/conftest.py:413` — docstring mentioning the path.
   - `tests/e2e/test_path_to_live_smoke.py:202` — docstring mentioning the path.
   - `RUNBOOK.md:385` — operator doc mentioning the path.

   The e2e tests are docker-gated (`bootstrap_stack`) and are **not** run in this task.

   **Do not investigate** why that fixture's `/run` write appeared to succeed (it `pytest.fail`s
   on a non-zero exit) while the app's write fails — it turns on whether `compose exec` runs as
   root, and `/tmp` is correct under either answer. Closed question; spend no context on it.

4. No other test needs touching: all 20 `_MLGATE_MARKER_PATH` references in
   `services/trading-engine/tests/` monkeypatch the constant with a `tmp_path` value, so the
   change is test-neutral.
