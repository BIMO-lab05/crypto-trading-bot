### 1. A running application service owns GSD planning state → unreadable tracked file → git index operations abort — **HIGH, mechanism CONFIRMED**

**Evidence**
- `docker-compose.unified.yml:329` (api-gateway service block): `- ./.planning/state:/app/planning_state:rw`
- `docker-compose.unified.yml:~310`: `PREFLIGHT_CARRY_INS_PATH=${PREFLIGHT_CARRY_INS_PATH:-/app/planning_state/carry_ins.json}`
- `services/api-gateway/app/routes/preflight_carry_ins.py` — the route **reads and writes**: `:146` `read_text(...)`, `:220` `_atomic_write_json(carry_ins_path, write_payload)`

- `stat .planning/state/carry_ins.json` → `mode=600 owner=uid 999:systemd-journal mtime=2026-07-30 01:40:46 +0100`
- `git ls-files .planning/state/` → the file is **tracked**
- `cat` → `Permission denied`; `git diff --stat` → `fatal: cannot hash` (quoted above)

**Interpretation**
The container process (uid 999, umask 077) rewrote the bind-mounted host file at 01:40. Because the file is tracked, every git command that hashes the worktree (`git diff`, `git add -A`, `git stash`, `git commit -a`) now aborts. The uncommitted content of that file is also unreadable to the repo user, so the delta cannot be inspected or preserved without elevated privileges.

**Why STATE.md's OP-13 is not enough:** it prescribes `chown` only. api-gateway rewrites the file on the next preflight state write, and the 600/999 ownership returns. Note also that switching the mount to `:ro` would **break** the feature — the route writes, it does not only read. Durable options: run api-gateway as the host uid, or point `PREFLIGHT_CARRY_INS_PATH` at a non-repo location (named volume) and have GSD read from there.
