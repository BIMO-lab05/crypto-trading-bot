## Decisions Made

See `key-decisions` in frontmatter. Headline calls:

1. **No jq dependency.** JSON building uses inline `python3 -c` with environment-variable indirection — Python is already required by the helper, and env-var indirection sidesteps any shell-injection concern from operator-supplied URL strings (threat T-11.1-03-05 in the plan threat model).
2. **Paper-only refusal fires FIRST.** Even `--help` under `TRADING_MODE=LIVE` is rejected. The deny-list-first pattern mirrors `run_evidence_loop.py` and means the test suite can use exit code 1 (refusal) vs 2 (URL_FORMAT_INVALID) as separable signals.
3. **Status = `AWAITING_HUMAN`, not `COMPLETE`.** The harness records validated evidence but cannot itself flip the carry-in row in `.planning/state/carry_ins.json` (operator commit required). This matches the schema's intent for AWAITING_HUMAN: "harness ran successfully but a wall-clock operator action is still required."
4. **Evidence JSON re-emitted with `extra` block.** The Wave 1 helper merges `extra` into the root payload (schema allows it via `additionalProperties: true`), but downstream consumers (tests + the future LIVECLOSE-INDEX.md aggregator) benefit from a stable nested location. Top-level copies are kept for back-compat.
