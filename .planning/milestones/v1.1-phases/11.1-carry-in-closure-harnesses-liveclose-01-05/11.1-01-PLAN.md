<objective>
Establish the shared evidence-schema + index + common helper module that all five LIVECLOSE harnesses (LIVECLOSE-01..05) build on. This plan creates Wave 1 foundations only: it does NOT write any of the five harness scripts (those are Plans 2-6 in Wave 2).

Purpose: every Phase 11.1 harness must emit a machine-readable evidence file conforming to a single JSON Schema (per ROADMAP Phase 11.1 Success Criterion #7). Without this Wave 1 foundation, Wave 2 plans would each invent their own JSON shape and the LIVECLOSE-INDEX.md table would drift. Shipping the schema + common helper first locks the contract and prevents Wave 2 drift.

Output:
- `.planning/evidence/_schema.json` — Draft 2020-12 JSON Schema with `schema_version: 1`, required fields, fixed `status` enum, and `additionalProperties: true` so each harness can add its own payload (e.g., `ci_url`, `verdict`, `row_count`) without bumping schema_version.
- `.planning/evidence/LIVECLOSE-INDEX.md` — template with placeholder rows; Plan 7 fills in actual harness paths after Wave 2 completes.
- `scripts/closure/_common.py` — `write_evidence()` helper that validates payload against the schema before writing, plus a `STATUS_*` enum and `load_schema()` helper.
- `tests/closure/test_common_evidence_writer.py` — pytest covering schema-pass and schema-fail branches of `write_evidence()`.

Decisions locked here (referenced by Plans 2-6):
- Common module is **Python-only** (`scripts/closure/_common.py`). Bash harnesses (Plans 2, 6) invoke `python -m scripts.closure._common write-evidence ...` rather than duplicating JSON writing in bash. Bash callers do NOT touch JSON directly.
- Schema status enum: `COMPLETE | AWAITING_HUMAN | INSUFFICIENT_DATA | FAILED` (these four; no others).
- Schema is **closed-for-extension after this plan** — Plans 2-6 MUST NOT modify `_schema.json` or `_common.py`. They consume read-only.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → harness CLI | Operator supplies CI URLs, evidence paths, status strings via argparse. Untrusted strings cross here. |
| harness → filesystem | Harnesses write evidence files into `.planning/evidence/LIVECLOSE-*/`. Repo-tracked path; commits review the diff. |
| `_common.py` → `_schema.json` | Schema is consumed read-only by every harness. A corrupt/missing schema breaks all five. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.1-01-01 | Tampering | `_schema.json` | mitigate | Schema loaded via `load_schema()` which raises on absence; `jsonschema.Draft202012Validator.check_schema()` called at Task 1 verify-time catches malformed schema before any harness runs against it. |
| T-11.1-01-02 | Information disclosure | evidence JSON files | accept | Evidence files contain CI URLs, timestamps, row counts, verdict strings — no secrets. `.env` already gitignored; no API keys or DB credentials flow through `write_evidence()` (the helper signature does not accept opaque blobs). |
| T-11.1-01-03 | Denial of service | `_common.py` CLI | accept | Single-shot script; no loops; no long-running I/O; argparse rejects malformed input. Not exposed to network. |
| T-11.1-01-04 | Spoofing | LIVECLOSE-INDEX.md | mitigate | Index is a static markdown; Plan 7 wires real harness paths under code review. The `<filled-by-plan-7>` placeholder is a grep-able tripwire — a Wave 3 review surfaces any forgotten cell. |
| T-11.1-01-05 | Elevation of privilege | scripts/closure/_common.py | accept | Script runs with operator-level filesystem perms; no setuid; no shell-out beyond argparse-validated args. |
</threat_model>
