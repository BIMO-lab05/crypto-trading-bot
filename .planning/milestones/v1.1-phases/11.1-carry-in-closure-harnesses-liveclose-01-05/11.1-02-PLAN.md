## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → harness | Operator may pass `$1` repo URL; otherwise harness reads from current repo. URL is passed to `git clone` — must not be operator-supplied shell metacharacters. |
| harness → docker daemon | Harness invokes `docker compose up/down/ps`. Docker daemon runs with operator perms; harness does not setuid. |
| harness → bootstrap.sh | Existing trusted script; harness only invokes, does not modify. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.1-02-01 | Tampering | bootstrap.sh invocation | accept | bootstrap.sh is part of the trusted code path (Phase 1 shipped, INFRA-02). Harness only calls it; tampering would be detected by git review of harness diff. |
| T-11.1-02-02 | Spoofing | repo URL arg | mitigate | Harness validates `$1` via `git ls-remote "$1"` before clone to catch typos/SSH host substitution; falls back to `git remote get-url origin` if unset. No shell-eval of the URL. |
| T-11.1-02-03 | Tampering | trap-handler cleanup | mitigate | `trap docker compose -f "$TMP_CLONE_DIR/docker-compose.unified.yml" down ... EXIT` runs against the tmp clone path — never the operator's working tree. Defensive guard refuses to run if `$PWD == $ORIG_REPO_ROOT` and `$TMP_CLONE_DIR` is unset. |
| T-11.1-02-04 | Elevation of privilege | bash injection via env | accept | Harness does not eval untrusted env input; argparse on the Python side validates `--extra-json`. Shell args are all quoted (`"$VAR"` form). |
| T-11.1-02-05 | Information disclosure | tmp clone retains .env after run | mitigate | trap-handler also runs `rm -rf "$TMP_CLONE_DIR"` after `docker compose down` (default behavior; disable via `LIVECLOSE_01_KEEP_TMP=1` for debugging). The cloned repo's `.env` is provisioned from `.env.example` by bootstrap.sh and contains no production secrets, but cleanup is still defense-in-depth. |
| T-11.1-02-06 | Denial of service | trap-handler bypass | accept | If the operator kills the harness with SIGKILL the trap does not fire; tmp dir leaks. Acceptable for an operator-driven script (operator can `rm -rf /tmp/liveclose-01.*` manually). |
</threat_model>
