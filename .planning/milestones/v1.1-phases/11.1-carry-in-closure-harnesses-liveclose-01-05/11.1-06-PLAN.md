<objective>
Deliver the LIVECLOSE-05 LIVE-flip smoke harness + runbook + e2e test. The harness documents the exact `docker compose ... up -d --force-recreate api-gateway` recipe with `TRADING_MODE=LIVE`, an inline `curl` probe asserting `GET /api/preflight/live-readiness` returns the LIVE-mode marker, and a tear-down revert step. The runbook describes the operator workflow. The e2e test runs against the existing PAPER-mode container and asserts the revert path restores PAPER — without ever flipping the real api-gateway to LIVE during pytest.

**Critical safety constraint** (per advisor): the harness script is **operator-runnable**, but the e2e test MUST NOT execute the LIVE flip path during pytest. The test asserts (a) the script's docker-compose recipe string is correct, (b) the curl probe contract is correct, (c) reverting restores PAPER mode. The script itself short-circuits in `LIVECLOSE_05_SUPERVISED_RUN=0` mode (the default — refuses to flip without explicit operator supervision flag).

Purpose: LIVECLOSE-05 is the operator-action carry-in for OP-01 (DASH-03 LIVE-flip manual smoke). The harness exists to (a) lock the exact docker-compose recipe and curl probe contract operators must follow, (b) provide a runbook reference, (c) ensure the revert step actually restores PAPER mode (verified by pytest). It does NOT and MUST NOT replace the operator's manual visual inspection of the rose viewport outline + red MODE pill (that remains the `human_needed` operator action — the screenshot is operator-only).

- `scripts/closure/liveclose-05-live-flip-smoke.sh` — bash harness documenting the recipe; refuses to actually flip without `LIVECLOSE_05_SUPERVISED_RUN=1`; on supervised run, executes the flip + curl probe + revert sequence with verbose logging.
