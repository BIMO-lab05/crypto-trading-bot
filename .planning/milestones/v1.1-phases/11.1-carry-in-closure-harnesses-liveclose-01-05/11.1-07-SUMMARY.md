## Decisions Made

- **No `--run-all` flag.** The task prompt summary mentioned `--run-all` to execute the 4 paper-safe harnesses sequentially. The plan body Task 2 (point 4) explicitly forbids auto-iteration: *"NEVER auto-iterate over the five harnesses… The orchestrator is read-mostly."* Threat model T-11.1-07-01 enforces this. Implemented only `--list` (default), `--status`, `--help`, and `--exec <ID>` per the plan body.
- **Env var name: `LIVECLOSE_05_SUPERVISED_RUN`** (not `LIVECLOSE_SUPERVISED` as the task prompt summary suggested once). The on-disk `liveclose-05-live-flip-smoke.sh` guard checks `LIVECLOSE_05_SUPERVISED_RUN=1`; the INDEX command literal and run-all.sh refusal both reference the same name so operators don't get redirected.
- **Carry-in ID mapping conservative.** `.planning/state/carry_ins.json` tracks `OP-01..04` and `INFRA-02`, not `LIVECLOSE-0X`. Only the 1:1 mappings (LIVECLOSE-01 ↔ INFRA-02, LIVECLOSE-05 ↔ OP-01) are wired. LIVECLOSE-02/03/04 are evidence that *contributes to* OP-04/02/03 closure but is not 1:1 — those print `state: unknown`. Inventing a synthetic mapping risks silent drift; explicit `unknown` is safer.
- **INDEX surfaces both module-form and file-path form** for `.py` harnesses. The plan acceptance grep gate uses module form (`scripts.closure.liveclose_03_psr_evidence`) while the harness-paths-exist-on-disk test needs file-path form (`scripts/closure/liveclose_03_psr_evidence.py`). The Conventions section explicitly documents both.

**2. [Rule 3 — Blocking] Plan markdown-lint heuristic incoherent on line-based grep**

- **Found during:** Writing `test_index_markdown_lints_clean`.
- **Issue:** Plan Task 1 acceptance step #7 says: *"`grep -c "^\n\n$" .planning/evidence/LIVECLOSE-INDEX.md` returns 0"*. That regex is incoherent — `grep -c "^\n\n$"` is a line-based grep with no embedded-newline interpretation and will always return 0 regardless of file content. Interpreting the intent: no trailing whitespace, ends with `\n`, no 3+ consecutive blank lines.
- **Fix:** Implemented the test via `re.search(r"\n[ \t]*\n[ \t]*\n[ \t]*\n", index_text)` + `text.endswith("\n")` + line-by-line `line == line.rstrip()` check, all in Python (`re` module, no grep).
- **Files modified:** `tests/closure/test_liveclose_index_wired.py`.
- **Verification:** `test_index_markdown_lints_clean` passes on the populated INDEX; passed on the unpopulated template too (lint heuristic only fires on actual drift).

- **Issue:** Plan calls for 6 orchestrator tests but doesn't pre-check the script exists + parses. Subprocess-driven tests would all fail with "no such file" or "syntax error" before reaching their assertions, producing confusing test output.
