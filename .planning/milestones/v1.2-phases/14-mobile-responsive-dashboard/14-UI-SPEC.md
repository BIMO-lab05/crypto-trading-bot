# Phase 14 — UI Design Contract

> Visual and interaction contract for the Mobile Responsive Dashboard phase.
> **Scope is responsive layout reflow over existing components.** No redesign,
> no new copy, no new components, no token additions beyond `theme.screens`.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Scope Reminder

This phase introduces:

1. Standardized Tailwind breakpoint tokens (`sm/md/lg/xl`) in `theme.screens`.
2. Per-component reflow class signatures so 4 named surfaces render
   correctly at ≤768px without horizontal scroll.
3. Touch-target contract (≥44px) on every interactive element (WCAG 2.5.5).
4. Two CI-checkable invariants: zero-horizontal-scroll and anti-`hidden`-on-mobile-data.

This phase **does not** introduce: new colors, new fonts, new copy, new components,
new design tokens (other than `theme.screens`), or visual redesigns of any surface.
Existing visual language is preserved verbatim.

## Spacing Scale

Inherited from Tailwind defaults (4px-multiple scale). No phase additions to
`theme.spacing`. The existing `spacing.extend` custom values (`'18': '4.5rem'`,
`'88': '22rem'`, `'112': '28rem'`, `'128': '32rem'`) are inherited dashboard-layout
shorthands; this phase does not touch them.

Declared values used by Phase 14 reflow work (multiples of 4):

| Token | Value | Usage in Phase 14 |
|-------|-------|-------------------|
| xs (`gap-1`) | 4px | Icon-to-label gap inside chip rows |
| sm (`gap-2`) | 8px | Stack-tile inner padding compaction |
| md (`gap-4`) | 16px | Default flex/grid gap between stacked tiles ≤768px |
| lg (`gap-5`/`gap-6`) | 20-24px | Section padding inherited from `Dashboard.jsx` (existing `gap-5`) and section breaks |
| xl (`py-8`, `px-8`) | 32px | Major section breaks (inherited) |
| 2xl | 48px | Page-level rhythm (inherited; not phase-introduced) |
| 3xl | 64px | Page-level rhythm (inherited; not phase-introduced) |

**Touch-target exception:** every `<button>`, `<a>`, and `[role="button"]` MUST
render with `min-height: 44px` (WCAG 2.5.5 Level AAA tappable target). This is a
**new contract** introduced by Phase 14. Implementation: add `min-h-[44px]`
utility (or `min-h-11` once `theme.spacing` is confirmed to include `11 = 2.75rem
= 44px` — Tailwind default does) to interactive elements on the 4 reflowed surfaces.

Exceptions to the 44px rule: **none** for surfaces in scope. Decorative
icon-only spans without click handlers are not interactive elements and not
subject to the rule.

To be declared in `frontend/tailwind.config.js`. Two equivalent shapes —
executor picks one based on the `2xl:` verification step below:

**Option A — `theme.screens` (replaces Tailwind defaults; recommended given

```js

  screens: {
    sm: '640px',
    md: '768px',
    lg: '1024px',
    xl: '1280px',
  },
  extend: { /* existing colors, spacing, fontFamily, etc. */ }
}
```

**Option B — `theme.extend.screens` (additive; preserves Tailwind's default

```js
  extend: {
    screens: {
      sm: '640px',
      md: '768px',
      lg: '1024px',
      xl: '1280px',
    },
    /* existing colors, spacing, fontFamily, etc. */
  }
}
```

These four values align with Tailwind defaults; the phase contract **requires
explicit declaration** so future utility additions cannot drift. `2xl` is
intentionally **omitted from the Phase-14 contract** (no phase-14 surface
targets ≥1536px).

- Executor MUST re-run this grep at implementation time and pick Option B if

### Per-Component Reflow Class Signatures

Transcribed from `14-CONTEXT.md <decisions>` so the executor has a single
authoritative source. Executor MAY tune exact `gap-N` values within Claude's
discretion bounds (CONTEXT.md), but the **class-pattern shape is contract**.

| Component | Path | ≤768px (mobile) shape | ≥768px (md+) shape |
|-----------|------|-----------------------|---------------------|
| `Dashboard.jsx` (grid sections) | `frontend/src/components/Dashboard.jsx` | `flex flex-col gap-N` (stacked tiles, render order preserved) | `md:grid md:grid-cols-N` (preserves existing density at `lg:grid-cols-3` / `xl:grid-cols-3` per existing code) |
| `PathToLiveTile.jsx` (chip rows + carry-in rows) | `frontend/src/components/PathToLiveTile.jsx` | `flex flex-col` rows; each row `w-full` | `md:flex-row md:flex-wrap` rows; each row `md:w-auto` |
| `KeyMetricsStrip.jsx` (metric cards) | `frontend/src/components/KeyMetricsStrip.jsx` | `grid grid-cols-2 gap-N` (no horizontal scroll on phone) | `md:flex md:overflow-x-auto md:gap-N` (existing horizontal layout preserved) |
| `TournamentDashboard.jsx` (table view) | `frontend/src/pages/TournamentDashboard.jsx` | `<div className="md:hidden">…stacked card list…</div>` (visible on mobile, hidden ≥md) | `<table className="hidden md:table">…existing table…</table>` (hidden on mobile, visible ≥md) |
| `TournamentFilterChips.jsx` (filters) | `frontend/src/components/TournamentFilterChips.jsx` | `flex flex-wrap` (chips wrap onto multiple lines, never horizontal-scroll) | `md:flex-nowrap` if density allows; otherwise keep `flex-wrap` |

**Information-preservation invariant:** every piece of data shown at ≥1280px
MUST also be reachable at ≤768px. Reflow is allowed; **mobile-hiding**
patterns (`hidden md:block` / `hidden md:flex` / etc.) on data-bearing
elements are forbidden (CI enforced — see anti-pattern gate below). Note the
direction: `md:hidden` (the dual-render desktop-hide branch) is **permitted**
on data carriers because the paired `hidden md:block` / `hidden md:table`
branch carries the same `data-testid` and keeps the data visible on mobile.

**Tile render order:** preserved across breakpoints. No reordering.

**Outer padding pattern:** retain existing `max-w-7xl mx-auto px-4 sm:px-6
lg:px-8` on root containers. Extend the pattern to reflowed sections rather
than introducing a new pattern.

**`data-testid` discipline:** every tile, metric card, chip, and row keeps its
existing `data-testid` across both render branches (mobile and desktop). For
the `TournamentDashboard.jsx` dual-render path, the same `data-testid` MUST
appear on both the mobile card and the desktop table row so Playwright queries
locate exactly one visible element at each viewport (depending on which
branch's media-query is currently matched).

### Anti-Pattern Gates (CI-enforced)

These are the contract's machine-checkable forbid-list:

1. **Zero-horizontal-scroll invariant.** For every element with a
   `data-testid` at viewports 375×667 and 768×1024:
   `boundingBox.x + boundingBox.width <= window.innerWidth`. Hard zero-tolerance
   (no float epsilon). Enforced by `tests/e2e/test_responsive_dashboard.py`.

2. **Touch-target invariant.** Every `<button>`, `<a>`, and `[role="button"]`
   has computed `min-height >= 44px` at both viewports. Enforced by the same
   Playwright test file.

3. **Anti-`hidden`-on-data invariant (direction-aware).** No element matching
   `data-testid="(metric|tile|chip|row)-*"` may carry a **mobile-hiding**
   class. The forbid-list is:
   - `display: none` (style attr — only forbidden when the element has no
     desktop-visible paired branch)
   - `hidden md:block`
   - `hidden md:flex`
   - `hidden md:grid`
   - `hidden md:table`
   - `hidden md:inline` / `hidden md:inline-block`
   - any other `hidden <md+>:*` family member

   **`md:hidden` is explicitly PERMITTED** on data carriers — it is the
   desktop-hide branch of dual-render (mobile-only rendering), and the data is
   reachable via the paired `hidden md:*` branch carrying the same `data-testid`.
   Forbidding it would break `TournamentDashboard.jsx`'s card-vs-table reflow.

   Enforced by `tests/integration/test_no_mobile_hidden_data.py` (static grep
   over `frontend/src/**/*.jsx`). Allowlist by exact `data-testid` string with
   a mandatory `reason` field.

   **Scope clarification (load-bearing — read before changing the regex):**
   the gate **only** targets `data-testid` data-bearing elements. Decorative
   responsive spans without `data-testid` (e.g. the existing `hidden sm:inline`
   on the italic name in `KeyMetricsStrip.jsx:233` and `hidden md:inline` on
   the separator at `KeyMetricsStrip.jsx:260`) are **permitted** and must not
   trip the gate. The regex must match `data-testid="..."` adjacency, not
   class-only patterns.

4. **PathToLive banner visibility.** `[data-testid="path-to-live-banner"]`
   visible without scroll at both viewports — its state-token (DO-NOT-FLIP /
   ALMOST / READY) is the operator's first-glance answer and must never be
   below-the-fold on mobile.

## Accessibility & Responsive

Phase-14 contracts (machine-checkable, see Anti-Pattern Gates above):

1. **WCAG 2.5.5 Target Size (Level AAA):** every interactive element ≥44×44px.
2. **No horizontal scroll** at 375×667 or 768×1024 for any `[data-testid]`.
3. **Information preservation (direction-aware):** no **mobile-hiding** class
   (`hidden md:block` / `hidden md:flex` / `hidden md:grid` / `hidden md:table`
   / `hidden md:inline*` / `display: none` without paired branch) on data
   carriers (`data-testid` matching `(metric|tile|chip|row)-*`). `md:hidden`
   on the mobile-only branch of a dual-render pair is permitted and required
   for `TournamentDashboard`'s card-vs-table reflow.
4. **State-token visibility:** PathToLive banner state-token visible without
   scroll at both target viewports.

Inherited / not-phase-14 a11y concerns (documented for hand-off, not enforced
by this phase):

- Keyboard focus rings: existing `ring-dark-primary` / `ring-dark-success` /
  `ring-dark-danger` defined in `tailwind.config.js:264-267`; no phase-14 changes.
- Color contrast: existing palette is dark-first; not re-validated in this
  phase. Flag for future a11y audit if needed.
- Screen reader landmarks: existing `<section>` / `<nav>` semantics preserved;
  no phase-14 changes.

**Tested viewports** (Chromium via pytest-playwright matrix):

| Device | Viewport | Purpose |
|--------|----------|---------|
| iPhone SE | 375×667 | Smallest realistic phone target — primary mobile reflow proof |
| iPad portrait | 768×1024 | `md:` breakpoint boundary verification |

Untested (out of scope):

- Landscape orientation — covered implicitly by `md:` breakpoint logic; no
  separate orientation media queries.
- Tablets > 1024px — `lg:` and `xl:` breakpoints already verified by existing
  desktop smoke tests.
- True 320×568 (iPhone 5/SE 1st gen) — out of scope; phone target is iPhone SE
  2nd gen (375×667) and newer.
