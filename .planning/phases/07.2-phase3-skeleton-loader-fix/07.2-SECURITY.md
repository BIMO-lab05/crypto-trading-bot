| Threat ID | Category | Disposition | Status | Evidence |

| T-07.2-01-01 | Tampering (regression) | mitigate | closed | Predicate `error?.response?.status !== 503 && failureCount < 2` present on all 4 hooks: `frontend/src/pages/Phase3Dashboard.jsx:159` (mlQuery), `:181` (sentimentQuery), `:197` (mtfQuery), `:213` (signalQuery). Inline rationale comments at L156-158, L180, L196, L212 anchor reviewer attention. Regression coverage: `tests/integration/test_dashboard_smoke.py` walks Phase3Dashboard row from `06-TILE-AUDIT.json:291-306` on every run; reverting any of the 4 `retry` lines to `retry: 2` re-introduces the skeleton-loader-mid-retry race that fails the smoke (Phase 7.1's exact failure mode). 136.19s smoke green per `07.2-VERIFICATION.md:31`. |
| T-07.2-01-02 | Information disclosure (status fingerprinting) | accept | closed | The retry predicate reads `error.response.status`; this is React Query / axios's default error shape and is **already** observable to any browser DevTools user via the Network tab. The predicate does not expose anything new beyond what the response itself already carries. Browser-side fingerprinting of backend status is unavoidable for a SPA that talks to its own gateway. No CWE-209 surface introduced. |
| T-07.2-01-03 | Information disclosure (ErrorState content) | mitigate | closed | `frontend/src/components/TileState.jsx:150-182` `ErrorState` renders `Failed ({code}): {message}` where `message` resolves via fallback chain `response.data.detail → response.statusText → "request failed"` (L155-158). The chain explicitly **excludes** `axios.error.message` per the L146-149 docstring ("NEVER the raw axios `.message` field (security: may contain stack-trace fragments)"). Confirmed live render text per `07.2-VERIFICATION.md:42-44`: `"PHASE 3: AI-ENHANCED TRADING / Failed (503): Service ml-prediction unavailable / RETRY"` — only contains: page title (operator-set string from `Phase3Dashboard.jsx:339`), HTTP code, and service-name string from gateway's own 503 detail. No stack trace, no internal path, no secret. CWE-209 mitigated at component level. |
| T-07.2-01-04 | Tampering (audit roster drift) | mitigate | closed | JSON entry at `.planning/phases/06-dashboard-audit-safety-state/06-TILE-AUDIT.json:291-306` (`verdict: "FIXED"`, `data_testid: "phase3-dashboard"`). Markdown row at `.planning/phases/06-dashboard-audit-safety-state/06-TILE-AUDIT.md:57` with matching `verdict=FIXED`, matching `data_testid=phase3-dashboard`, no struck-through duplicate remains. Drift gate: smoke harness consumes the JSON; Markdown is reference-only. JSON corruption fails smoke at parse time. Markdown-only drift is documentation-grade only — does not affect runtime regression coverage. |
| T-07.2-01-05 | Tampering (other-page retry pattern unsurveyed) | accept | closed | Side observation per `07.2-01-SUMMARY.md:33` and `07.2-VERIFICATION.md:75`: Performance and Portfolio page hooks may use the same `retry: 2` config and exhibit the same skeleton-loader-mid-retry symptom under feature-flagged-off conditions. Out of scope for Phase 7.2 (`must_haves.goal` scoped to Phase3Dashboard's 4 hooks + audit-row re-include). Carried as accepted risk for v1.1 cleanup. No security degradation — the original skeleton-loader behavior is a UX defect, not a vulnerability. |
