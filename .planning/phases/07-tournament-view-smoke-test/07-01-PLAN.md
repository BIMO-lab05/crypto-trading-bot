<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → api-gateway | Unauthenticated browser/HTTP client to gateway (D-09 carryforward — read-only config disclosure posture); `tournament_id` URL path segment is attacker-controllable input. |
| api-gateway → disk | Gateway process reads from the RO bind-mount `/app/snapshots`. No write surface — RO mount enforced at compose layer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | /app/snapshots disk artifact | mitigate | RO bind-mount in docker-compose.unified.yml ensures the gateway has no `write` capability against the snapshot dir (`:ro` suffix on the mount). Tournament-harness owns writes under `--profile tournament`. |
| T-07-02 | Information Disclosure | GET /api/tournament/snapshots[/{id}] | accept | Carryforward of Phase 6 D-09: snapshots are git-tracked committed artifacts containing tournament metrics; no PII, no secrets, no balances, no positions. Unauthenticated read-only matches `/api/config/safety-state`. |
| T-07-03 | Tampering (path traversal) | GET /api/tournament/snapshots/{tournament_id} | mitigate | Two-layer defense: (a) regex gate `^[A-Za-z0-9_\-]+$` on `tournament_id` — rejects `.`, `/`, `\`, `..`, URL-encoded variants; (b) `Path(base).resolve().joinpath(f"{tid}.json").resolve().is_relative_to(base.resolve())` check — defense-in-depth against any future regex bypass. 400 response with detail `invalid tournament_id` on either failure. |
| T-07-04 | Denial of Service | GET /api/tournament/snapshots/{tournament_id} | mitigate | File-size cap: `Path.stat().st_size > 50 * 1024 * 1024` triggers a 500 response BEFORE the file body is read. Caps gateway memory exposure from a poisoned large snapshot. |
| T-07-05 | Denial of Service | GET /api/tournament/snapshots (list endpoint) | accept | Per-file `try/except (json.JSONDecodeError, OSError)` + `continue` ensures one bad file cannot 500 the listing. List response size is bounded by the number of committed snapshots (low cardinality — tens at most). |
| T-07-06 | Repudiation | both endpoints | accept | Read-only endpoints, no state mutation, no auditable action; existing access logs from FastAPI / uvicorn middleware suffice. |
| T-07-07 | Spoofing | client identity | accept | D-09 carryforward — these endpoints are intentionally unauthenticated. Same posture as `/api/config/safety-state`. |
| T-07-08 | Elevation of Privilege | filesystem mount | mitigate | `:ro` flag on the docker-compose bind-mount means even if the gateway process is RCE-compromised, the attacker has no write access to the committed snapshot artifacts. |
</threat_model>
