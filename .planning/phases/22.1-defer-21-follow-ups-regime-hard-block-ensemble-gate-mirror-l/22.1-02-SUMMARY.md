# Phase 22.1 Plan 02: Regime Hard-Block Ensemble Gate Summary

**The aggregator's regime hard-block now suppresses every ensemble leg pre-dispatch, keyed on the `regime_blocked` flag it already wrote — closing the last of the four HOLD causes whose decision two untyped legs were free to ignore.**

## Performance

- **Duration:** ~42 min
- **Tasks:** 2 of 2 (RED, GREEN)
- **Files modified:** 2
- **Test delta:** +10 collected (6 test functions, one parametrized ×5); `tests/strategies/` + `test_mtf_confidence_consolidation.py` went 205 → 215 passed

## Accomplishments

- **Closed DEFER-21-02.** `simple_rsi` and `mean_reversion` are dispatched off the indicator dict and never read `.action`, so before this change two of three legs traded straight past a system-level regime rejection. The RED run measured exactly that: `{'simple_rsi': 1, 'mean_reversion': 1}` on a blocked payload.
- **Added `REJECT_REGIME_BLOCKED`** so the funnel attributes the terminal state to this gate specifically, distinguishable from `REJECT_MTF_DEMOTED` and from a generic no-signal (T-22.1-02-03, Repudiation).
- **Kept the gate narrow.** It reads the flag, never the action. A dedicated narrowness test drives a requirements-gate HOLD (no regime keys) through to both legs and fails if the gate ever widens.
- **Kept it fail-open.** Five malformed values (`"true"`, `"True"`, `1`, `{}`, a nested dict) and a `None` metadata container all leave behavior exactly as it was (T-22.1-02-01, T-22.1-02-04).

## Evidence the gate is wired, not just tested

The gate keys on the boolean singleton `True`. That is the one way this change could pass all ten tests and still never fire in production: if the producer returned a `numpy.bool_(True)` (from a numpy/pandas comparison on the ADX payload) or an `int`, `is True` would be False and the gate would be dead code. Both links were therefore checked in **production source**, not in tests.

**Producer** — `services/trading-engine/app/aggregation/market_regime.py::apply_regime_adjustment`. `regime_blocked` is initialised to the Python literal `False` (`:510`) and set to the Python literal `True` (`:527`) on an explicit `elif is_counter_trend:` branch, then returned unmodified (`:568`, `return adjusted, reason, regime_blocked`). It is never derived from a numpy or pandas comparison — `analysis.adx` / `plus_di` / `minus_di` are read only to format the reason string. So the value on the wire is the real singleton.

**Write site** — `services/trading-engine/app/signal_aggregator.py:1256-1265` unpacks that third tuple element and assigns it to `metadata["regime_blocked"]` verbatim, with no coercion.

A note on what does **not** prove this, since it is the tempting citation: `tests/test_mtf_confidence_consolidation.py:359` asserts `result.metadata["regime_blocked"] is True`, but its `_run_mtf` helper monkeypatches `apply_regime_adjustment` itself (`:233-237`), so that `True` is the test's own literal travelling through. It is good evidence of non-coercing pass-through **at the write site** and nothing more. The producer claim above rests on reading `market_regime.py` directly.

Write site re-read at execution time (the plan warned these line numbers have gone stale three times): `services/trading-engine/app/signal_aggregator.py:1263-1265` writes `regime_blocked` and `regime_adjustment_reason` **flat** on metadata; `:1280` forces the action to HOLD. Both confirmed current.

## Decisions Made

- **`_ABSENT` sentinel rather than `None` for "key not written."** `regime_blocked` is written on every signal whose `regime_analysis` is truthy — `False` included — so "absent" and "False" are genuinely different production shapes and the builder must be able to produce both.
- **Two tests renamed after the first RED run.** `-k regime` (the plan's verify command) initially selected only 8 of 10 tests, because the None-container and narrowness tests did not carry "regime" in their names. Renamed to `test_none_metadata_container_does_not_trip_the_regime_gate` and `test_hold_without_a_regime_flag_still_dispatches_every_leg` so the plan's own selector covers the whole suite.
- **The None-container test asserts dispatch counts, not `out is not None`.** With `metadata=None` there is also no ATR payload, so whether the resulting signal emits is a different question from whether this gate fired. The positive control owns the emission assertion.
