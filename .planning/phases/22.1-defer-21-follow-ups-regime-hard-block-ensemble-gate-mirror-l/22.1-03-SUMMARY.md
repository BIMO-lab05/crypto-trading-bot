# Phase 22.1 Plan 03: SQZMOM Duplicate-Index Rejection Summary

`EnhancedSqueezeMomentum.calculate` now rejects a non-unique index with a logged, named `ValueError` raised before the `try`, closing the silent leg-dropout recorded as DEFER-21-01.

## What Was Built

A non-unique-index guard in the pre-`try` validation block of
`EnhancedSqueezeMomentum.calculate` (`services/technical-analysis/app/indicators/sqzmom_enhanced.py:892`),
plus the three-test regression suite that plan 21-01 had to withhold
(`services/technical-analysis/tests/test_sqzmom_duplicate_index.py`).

Placement is the load-bearing part. The guard sits at `:892`; the method's `try:`
opens at `:905` and its broad `except Exception` closes at `:1065`. Raised from
inside the `try`, the `ValueError` would have been swallowed straight back into
the `None` this item exists to remove.

The guard computes `df.index[df.index.duplicated()].unique()`, emits one
`logger.error` naming the duplicated labels and their count, then raises a
`ValueError` carrying the same detail.

## Deviations from Plan

### 1. [Rule 1 — Bug in the plan's own fixture recipe] The suggested duplicate position does not reproduce the defect

- **Found during:** Task 1, while verifying the RED failure was for the documented reason.
- **Issue:** Both the plan (`df.index.values[10] = df.index.values[9]`) and DEFER-21-01 suggest duplicating at index position 10. Measured, that returns a **full DataFrame and logs nothing** — the defect does not reproduce. `_determine_histogram_color` opens with `if pd.isna(momentum) or pd.isna(prev_momentum):`, and Python's `or` **short-circuits**. On a warm-up bar `sqz_momentum` is still NaN, so the first operand is already `True` and the ambiguous `pd.isna(<2-element Series>)` is never evaluated.
- **Measured:** `sqz_momentum` is NaN for positions 0–29 on this fixture (first valid at 30). Duplicating at 9→10 returns `DataFrame(400, 20)` with 0 ERROR records. Duplicating at 100→101, 200→201 and 250→251 each returns `None` with exactly 1 ERROR record (`The truth value of a Series is ambiguous`).
- **Fix:** `DUP_SRC = 200`, `DUP_DST = 201`, and `test_duplicate_index_raises_instead_of_dropping_the_leg` now **asserts** the chosen bar is past warm-up (`sqz_momentum` at `DUP_DST` is not NaN on a clean frame). Without that assertion the entire suite would have passed against unfixed code — it nearly did: the first RED run used position 10 and reported `DID NOT RAISE` for the wrong reason (the frame computed successfully rather than returning `None`).
- **Files modified:** `services/technical-analysis/tests/test_sqzmom_duplicate_index.py`
- **Commit:** `064a42d`

### 2. [Documentation] Test 2 strengthened beyond the plan's wording

- **Found during:** Task 1 design.
- **Issue:** The plan specifies test 2 as "assert a record was emitted" at ERROR level. That assertion is satisfied by the **pre-fix** code too — the broad `except Exception` already logged `Error calculating Enhanced Squeeze Momentum: ...` before returning `None` (confirmed: exactly 1 ERROR record pre-fix). As written it would have been green in the RED state, violating the plan's own acceptance criterion.
- **Fix:** Test 2 asserts **exactly one** ERROR record on this module's logger, that its message names the duplicated label, and that it says why the frame was rejected (`"unique" in message.lower()`). More than one record would mean the raise travelled through the broad handler, i.e. the guard was placed inside the `try`. The `pytest.raises` wrapper keeps it red pre-fix with `DID NOT RAISE`, as the criterion requires.
- **Commit:** `064a42d`
