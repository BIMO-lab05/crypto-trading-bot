<decisions>
## Implementation Decisions

### A. DEFER-21-02 - regime hard-block must gate `simple_rsi` / `mean_reversion` (behavioral)
- Half the machinery exists: `services/trading-engine/app/signal_aggregator.py` already writes `primary_signal.metadata["regime_blocked"]` (observed at `:1266` on 2026-08-27 - **re-read before editing; sa.py line numbers have gone stale 3x across phase-21 docs**).
- Fix mirrors plan 21-05's MTF gate exactly: in `multi_strategy_ensemble.py`, gate legs 1/3 (simple_rsi, mean_reversion) when `metadata.get("regime_blocked") is True` - **identity check, not truthiness**, with a fail-open container guard (missing/malformed metadata = no gate), same doctrine as the `demoted_to_hold` gate at `multi_strategy_ensemble.py:~710-748`.
- **Do NOT gate on `action == HOLD`** - that collapses four upstream causes (raw HOLD consensus, per-timeframe requirements gate, MTF demotion, regime block) into one signal; plan 21-05 refused this deliberately and the refusal stands.
- The 21-05 pinning test `test_regime_hard_block_hold_is_not_recorded_as_an_mtf_demotion` must stay green unmodified - it asserts regime HOLD is not an MTF demotion, which remains true.
- New test mirrors the MTF gate test shape (see `test_ensemble_leg_wiring.py` / 21-05 tests for the pattern).
- **Declared behavior change:** admission tightening - fewer trades in counter-trend regimes. Operator ratified this direction 2026-08-27. Note it in the SUMMARY; no ablation required (same class as the already-measured MTF gate).

### B. DEFER-21-03 - three non-CONTEXT mirror literals in `signal_aggregator.py` (mechanical)
- Sites as of `20fd333` (re-verify): `:135` `period: int = 9` (fetch_rsi default), `:235` `"std_dev": 2.5` (bollinger request), `:356` `"limit": 300` (trend-filter kline limit).
- Route each through the engine's own `Settings` per the P21-7 pattern (plan 21-07). **Values do not change** - 9, 2.5, 300 become Settings defaults with the same numbers.
- Extend `services/trading-engine/tests/aggregation/test_mirror_literals.py` to cover the three sites.
- These are NOT locked thresholds (locked set: MIN_AGREEING_LEGS=1, AGGREGATION_THRESHOLD=0.10, min_signal_confidence=0.30 - untouched, threshold-lock guard test must stay green).

### C. DEFER-21-04 - adx_period survivors (mechanical)

### D. DEFER-21-05 - regime confidence hardcoded 0.7 -> adopt TA's real value (behavioral, measured)
- `services/trading-engine/app/handlers/signals.py:212` returns `"confidence": 0.7` while TA computes and returns a genuine confidence on the same ADX response (`fetch_adx` already reads the `confidence` key - verify at execution).
- Adopt TA's value; keep the existing degraded-path defaults for absent/malformed responses.
- **This is a numeric behavior change**: feeds the 0.15-weight leg of `_calculate_enhanced_signal`. Deliverable includes a before/after measurement (script over recent live TA payloads comparing old-vs-new weight outputs, ablation-script pattern from `scripts/ablation_ensemble_admission.py`), documented in the SUMMARY.
- Expected live impact ~zero (live trading runs the ensemble path, not the enhanced path) - the measurement proves it rather than asserts it.

### E. DEFER-21-01 - SQZMOM silent leg dropout on duplicate index (TA service)
- `services/technical-analysis/app/indicators/sqzmom_enhanced.py`: duplicate index label makes `calculate` raise internally (`.loc[row.name]` on non-unique index returns a Series) and the broad `except` returns `None`; the SQZMOM leg silently vanishes from the vote (`handlers/analysis.py:118` guard).
- Fix per deferred-items suggestion: **reject a non-unique index at the top of `calculate` with an explicit, logged error** - loud failure, not silent None. (Full positional-indexing rewrite of every `.loc[row.name]` site is NOT required once the input is rejected up front.)
- Add the duplicate-index regression test (may now land green since the fix ships with it; the testing.md no-red-test rule was the only reason it was withheld in 21-01).
- TA service must be rebuilt + force-recreated for this item.
