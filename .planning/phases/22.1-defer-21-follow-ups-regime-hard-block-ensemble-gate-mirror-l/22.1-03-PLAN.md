<objective>
Close DEFER-21-01: an input frame carrying a duplicate index label makes
`EnhancedSqueezeMomentum.calculate` raise internally (a `.loc[row.name]` lookup
on a non-unique index returns a Series, and the surrounding arithmetic raises),
the module's broad `except Exception` swallows it, and `calculate` returns
`None`. The caller guard then drops the SQZMOM leg from the aggregate vote with
no error surfaced — the endpoint returns a perfectly well-formed response
computed from one fewer voter.

Purpose: a silent `None` from a voting indicator is the harder failure mode to
notice. TimescaleDB kline history in this repo has a documented record of holes
and repairs, so a duplicate timestamp reaching the indicator is a live
possibility, not a theoretical one.

Output: an explicit, logged rejection of a non-unique index at the top of
`calculate`, placed BEFORE the `try` so it escapes the swallowing handler, plus
the regression test that 21-01 had to withhold (it can land green now because
the fix ships with it).

Scope: the full positional-indexing rewrite of every `.loc[row.name]` site is
explicitly OUT of scope (22.1-CONTEXT Deferred Ideas) — rejecting the input up
front makes it unnecessary.
</objective>
