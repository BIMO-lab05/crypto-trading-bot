<feature>
  <name>Regime hard-block suppresses every ensemble leg</name>
  <files>services/trading-engine/app/strategies/multi_strategy_ensemble.py, services/trading-engine/tests/strategies/test_ensemble_confidence_units.py</files>
  <behavior>
    Given an aggregator signal whose `metadata["regime_blocked"]` is the boolean
    `True`:
      - `generate_signal` returns None
      - zero dispatches to `SimpleRSIStrategy.generate_signal`
      - zero dispatches to `MeanReversionStrategy.generate_signal`
      - `self.last_rejection` reports `REJECT_REGIME_BLOCKED`
      - one log line at INFO naming the regime block and its reason

    Given `metadata["regime_blocked"]` absent: both legs dispatch (unchanged).
    Given `metadata["regime_blocked"]` explicitly `False`: both legs dispatch.
    Given `metadata["regime_blocked"]` set to the string `"true"`, the string
      `"True"`, the integer `1`, or a dict: both legs dispatch — fail open, an
      untyped metadata entry must never be able to halt the whole ensemble.
    Given `metadata` is `None` or the attribute is missing entirely: both legs
      dispatch, no exception raised.
    Given a HOLD action with no `regime_blocked` flag (raw HOLD consensus, the
      per-timeframe requirements gate): both legs dispatch — the gate keys on
      the flag, never on `action == HOLD`.
  </behavior>
  <implementation>
    After the tests are red, add `REJECT_REGIME_BLOCKED = "regime_blocked"`
    alongside the existing rejection constants, and insert the gate immediately
    after the MTF gate in `generate_signal`, before any leg dispatch. Follow the
    MTF gate's four-paragraph doctrine comment structure (NARROW BY
    CONSTRUCTION / IDENTITY CHECK / NO THRESHOLD VALUE CHANGED /
    expected-effect) adapted to this cause. `logger.info` naming the block, then
    `self._reject(REJECT_REGIME_BLOCKED, <reason quoting metadata's
    regime_adjustment_reason>)`, then return None.
  </implementation>
</feature>
