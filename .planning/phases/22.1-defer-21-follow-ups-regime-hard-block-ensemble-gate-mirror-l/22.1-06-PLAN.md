<!-- Environment facts the executor needs. -->

Compose file: `docker-compose.unified.yml` ONLY. The plain `docker-compose.yml`
is incomplete (no postgres/timescaledb/redis/rabbitmq) and disagrees on values.

Container names: `crypto-bot-trading` (trading-engine, port 8005) and
`crypto-bot-ta` (technical-analysis, port 8004).

Known environment hazards, all documented:
- BuildKit hangs on WSL2 — prefix builds with `DOCKER_BUILDKIT=0`.
- Docker credential helper dies with "error listing credentials" — `export DOCKER_CONFIG=$(mktemp -d)`
  before building.
- Docker context must be `default` (Unix socket), not `desktop-linux` —
  `docker context show`.
- After a host suspend, Docker Desktop has staged directories over single-file
  bind mounts and postgres/timescaledb/prometheus die with `exit=127`
  "not a directory". Fix is `docker compose -f docker-compose.unified.yml up -d --no-deps --force-recreate <service>`.
- WSL bind-mount race: `docker inspect` shows a bind mount while the path inside
  is empty and root-owned, surfacing as `PermissionError` writing `/app/logs`.
  Same fix: `--force-recreate`.
- `docker exec crypto-bot-trading pytest tests/` collects ZERO tests (OP-14:
  missing PyJWT, empty `/app/shared`, conftest path assumptions). Do NOT try to
  run the suite in-container — run suites on the host and use `docker exec` only
  for grep proofs.

Never touch during this plan: `prefer_maker_orders`, `AUTO_TRADING_ENABLED`, the
kill-switch file `safety/EMERGENCY_STOP`, any risk cap, `.env`.

Verification standard (CLAUDE.md section 7): an HTTP 200 alone is not proof. For
this phase the four legs are — code present in the running container (grep),
service healthy after recreate, host suites green against a baseline, and the
config-drift guards green.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host source tree → container image | code that is green on the host may be absent from the process actually serving |
| operator commands → live paper trader | a rebuild touches a service that can place simulated orders |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22.1-06-01 | Spoofing | "shipped" claimed from a stale container | mitigate | `--force-recreate` plus `docker inspect` creation timestamps plus in-container identifier greps; no claim rests on an HTTP 200 alone |
| T-22.1-06-02 | Tampering | rebuild sweeping in unrelated services | mitigate | Services rebuilt one at a time by name; `ps` diff against a recorded baseline must touch only the two changed services |
| T-22.1-06-03 | Denial of Service | recreating a service into the documented post-suspend bind-mount failure | mitigate | Baseline `ps` captured first; `--no-deps --force-recreate` is the recorded remedy and any repair is noted as pre-existing rather than phase-caused |
| T-22.1-06-04 | Elevation of Privilege | accidental arming of the live/auto path during deploy | mitigate | Explicit prohibition on touching `PAPER_TRADING_MODE`, `TRADING_MODE`, `AUTO_TRADING_ENABLED`, `prefer_maker_orders`, risk caps and the kill-switch file; kill-switch presence recorded unchanged |
| T-22.1-06-05 | Repudiation | a verification asserted rather than shown | mitigate | Every gate is a pasted command with its output and exit status; empty greps shown as empty, not summarized |
| T-22.1-06-SC | Tampering | package-manager installs | mitigate | The rebuild installs pinned requirements from the existing service images; no NEW dependency is added by this phase, so the Package Legitimacy Gate has no new rows. If a build introduces an unpinned or unexpected package, stop and report rather than proceeding |
