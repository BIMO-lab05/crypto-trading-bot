<objective>
Build the checkpointed iteration harness (INFRA-04) — a shell script that runs the integration suite, presents the failure log, lets the operator (or a wrapped Claude `-p` invocation) propose a fix, refuses to apply diffs that mute tests (mocks / skips / xfails / threshold lowering), and commits accepted fixes atomically. The harness is the structural mechanism that prevents the "iterate until green" Goodhart trap. The same anti-mock regex set is exposed as a standalone script so the CI workflow (02-09) reuses it.

Purpose: Auto-iteration on test failures is a known anti-pattern — the cheapest path is to weaken assertions. INFRA-04 + D-12 forbid this; the script-level refusal makes the rule structural rather than aspirational.

Output: `scripts/iter-fix.sh` (operator entrypoint), `scripts/iter-fix-check-diff.sh` (reusable refusal logic), `tests/scripts/test_iter_fix.bats` (tests proving refusal patterns hit).
</objective>

1. Create `scripts/iter-fix-check-diff.sh` (mode 100755). The script reads a unified diff from stdin (or from `$1` if given), greps for refused patterns scoped to `tests/`, and exits 1 on hit with a clear message. Pseudocode:

   ```bash
   #!/bin/bash
   # iter-fix-check-diff.sh — D-12 refusal logic. Reusable from iter-fix.sh AND .github/workflows/integration.yml.
   # Reads a unified diff from stdin (or $1 file path). Exits 1 if it adds banned patterns inside tests/.

   set -e
   RED='\033[0;31m'; YELLOW='\033[1;33m'; NC='\033[0m'

   # Source: stdin if no arg, else file
   if [ -n "$1" ]; then DIFF=$(cat "$1"); else DIFF=$(cat); fi

   # State machine: track current file via `+++ b/<path>` markers. Only enforce when
   # the active file path starts with tests/.
   refused=()
   current_file=""
   in_tests=false

   while IFS= read -r line; do
       if [[ "$line" =~ ^\+\+\+\ b/(.+)$ ]]; then
           current_file="${BASH_REMATCH[1]}"
           if [[ "$current_file" == tests/* ]]; then in_tests=true; else in_tests=false; fi
           continue
       fi
       if [ "$in_tests" = false ]; then continue; fi
       if [[ "$line" =~ ^\+ ]]; then  # addition line
           # banned imports / decorators
           if echo "$line" | grep -qE '(unittest\.mock|mocker\.patch|pytest\.skip|pytest\.mark\.xfail)'; then
               refused+=("$current_file: $line")
           fi
       fi
   done <<< "$DIFF"

   # Threshold-lowering heuristic: paired -/+ assert lines where the + side has a larger numeric.
   # Implemented via two-pass over the diff.
   # ... see implementation; key: extract paired assert numerics inside tests/ hunks ...

   if [ ${#refused[@]} -gt 0 ]; then
       echo -e "${RED}[REFUSED] D-12 anti-mock guard hit:${NC}"
       for r in "${refused[@]}"; do echo -e "  ${YELLOW}$r${NC}"; done
       echo "Refusal patterns: unittest.mock | mocker.patch | pytest.skip | pytest.mark.xfail | threshold-lowering"
       exit 1
   fi
   exit 0
   ```

2. Implement the threshold-lowering check. Approach: walk the diff hunks (block between `@@ ... @@` markers); inside each hunk that targets a file under `tests/`, capture pairs of `^-.*assert.*<\s*([0-9.]+)` and `^\+.*assert.*<\s*([0-9.]+)` on adjacent or near-adjacent lines (within the same hunk), and refuse if the `+` numeric is greater than the `-` numeric. This is heuristic — false positives possible (raise threshold to legitimately tighten elsewhere), but D-11 says "operator approves every diff" so the operator can override on review. The script's job is to surface the pattern, not adjudicate.

3. Create `tests/scripts/test_iter_fix.bats` (bash bats-style tests). Each test pipes a fixture diff into `scripts/iter-fix-check-diff.sh` and asserts exit code + output substring. The bats framework is already-or-easily-installable on dev machines and CI; if not present in the project, fall back to a `tests/scripts/test_iter_fix.sh` that runs each case and prints PASS/FAIL inline (use whichever harness already exists in the repo; if neither, write the inline-PASS/FAIL fallback).

4. Each test case fixture diff should be inlined as a heredoc in the test file (no separate `tests/scripts/fixtures/` tree needed). The 8 cases above each produce a small diff string; pipe and assert.

1. Create `scripts/iter-fix.sh` (mode 100755) with the following sequence:

   ```bash
   #!/bin/bash
   # iter-fix.sh — checkpointed iteration harness (INFRA-04, D-09..D-12).
   # Run integration suite; on first red, prompt operator for a fix; refuse anti-mock
   # patterns; commit atomically on approval. NO auto-retry, NO iterate-until-green.

   set -e
   RED='\033[0;31m'; GREEN='\033[0;32m'; YELLOW='\033[1;33m'; NC='\033[0m'

   SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
   REPO_ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"
   cd "$REPO_ROOT"

   # Step 1: run pytest, capture exit code + log
   echo -e "${YELLOW}[1/5] Running integration suite (pytest tests/integration -x)...${NC}"
   PYTEST_LOG="$(mktemp)"
   set +e
   pytest tests/integration -x 2>&1 | tee "$PYTEST_LOG"
   PYTEST_EXIT=${PIPESTATUS[0]}
   set -e
   if [ "$PYTEST_EXIT" -eq 0 ]; then
       echo -e "${GREEN}[2/5] All tests green. No fix needed. Exit.${NC}"
       rm -f "$PYTEST_LOG"
       exit 0
   fi
   echo -e "${RED}[2/5] First red at exit=$PYTEST_EXIT. Failure log saved to $PYTEST_LOG.${NC}"

   # Step 2: stop and hand control to operator. They (or a wrapped Claude -p) propose a fix
   # and stage it via `git add`. Do NOT auto-iterate.
   echo -e "${YELLOW}[3/5] Make a fix. Stage it with 'git add <files>'. Press ENTER when ready, or Ctrl-C to abort.${NC}"
   read -r _

   # Step 3: read the staged diff and run the anti-mock guard
   echo -e "${YELLOW}[4/5] Checking staged diff against D-12 refusal patterns...${NC}"
   if ! git diff --cached | bash "$SCRIPT_DIR/iter-fix-check-diff.sh"; then
       echo -e "${RED}[REFUSED] Staged diff hit D-12 anti-mock guard. Unstage and retry.${NC}"
       echo "  Run: git reset HEAD <files>"
       exit 1
   fi
   echo -e "${GREEN}        diff cleared D-12 guard.${NC}"

   # Step 4: print the diff for operator review
   echo -e "${YELLOW}[5/5] Review the diff and confirm:${NC}"
   git --no-pager diff --cached
   read -p "Apply? [y/N]: " ans
   case "$ans" in
       [yY]|[yY][eE][sS])
           # Step 5: prompt for one-line commit message + commit
           read -p "Commit message (fix(<service>): <one-line>): " msg
           if [ -z "$msg" ]; then
               echo -e "${RED}Empty commit message — aborting${NC}"; exit 1
           fi
           git commit -m "$msg"
           echo -e "${GREEN}Committed. Re-run pytest to verify.${NC}"
           ;;
       *)
           echo -e "${YELLOW}Skipped. Diff still staged. Run 'git reset HEAD' to unstage.${NC}"
           exit 1
           ;;
   esac

   # No auto-retry — D-13 carry-forward. Operator decides next step.
   echo -e "${GREEN}[done] One fix applied. Re-run scripts/iter-fix.sh to continue.${NC}"
   ```

2. Anti-iteration guard: the script DOES NOT loop on its own. It runs once: pytest → fix → check → commit. To iterate, the operator runs it again. This is the structural answer to "iterate until 3 green" (Goodhart trap, D-13 carry-forward).

3. Commit message validation is light (non-empty); operator-supplied. The CONTEXT-recommended format is `fix(<service>): <one-line>` — surfaced in the prompt text. No regex enforcement at this layer (operator discretion); future hook could enforce conventional-commits format.

4. Failed-attempt branch tagging via `wip(iter)` is mentioned in 02-PATTERNS.md as a future ergonomic — NOT included in this plan to keep the script under 100 lines and the surface small. Document deferral inline in a script comment.
