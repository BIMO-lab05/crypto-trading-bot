<objective>
Wire CI for the Phase 2 integration suite. New workflow `.github/workflows/integration.yml` runs on every push + PR: boots the stack via `bash bootstrap.sh` (same invocation operators use locally — D-07), runs `pytest tests/integration`, runs the anti-mock guard `scripts/iter-fix-check-diff.sh` against the PR diff (D-12), uploads logs on failure, tears down. Diverges from `live-smoke.yml` in two ways: deterministic (no `continue-on-error`), runs every push (not nightly).

ML-on variant runs as a separate workflow `.github/workflows/integration-ml-on.yml` on schedule + workflow_dispatch (CD-05 — nightly + manual). It re-uses the integration workflow shape but flips `ENABLE_ML_PREDICTIONS=true` and runs `pytest tests/integration -m ml_on`.

Purpose: The fresh-clone proof boundary (D-05) is empty without CI. CI also enforces the anti-mock guard structurally — operator can't merge a "test mute" diff via PR.

**Operator-action note (Warning #1):** The anti-mock guard is gated to `pull_request` events, not `push`. Direct pushes to `main`/`master` bypass it. The canonical defense is GitHub branch protection — operator MUST configure it before relying on this guard. Tracked in this plan's `<verification>` block; not enforced by code.

Output: Two GitHub Actions workflows.
</objective>

1. Create `.github/workflows/integration.yml`. Use the same shape as `live-smoke.yml` but diverge per planning_context. CRITICAL: never echo `TEST_TELEGRAM_BOT_TOKEN` to logs (GitHub auto-masks `secrets.*`, but defensive: don't put it on bash command lines).

```yaml
name: Integration Suite (Phase 2)

on:
  push:
    branches: ['**']
  pull_request:
    branches: [main, develop]

concurrency:
  group: integration-${{ github.ref }}
  cancel-in-progress: true

jobs:
  integration:
    name: pytest tests/integration (deterministic, tape mode)
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0  # required for `git diff origin/main..HEAD` in anti-mock guard

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.12'

      - name: Install pytest dependencies
        run: |
          python -m pip install --upgrade pip
          pip install httpx asyncpg pytest pytest-asyncio

      - name: Boot stack via bootstrap.sh in tape mode
        env:
          MARKET_DATA_SOURCE: tape
          PAPER_TRADING_MODE: 'true'
          TRADING_MODE: PAPER
          AUTO_TRADING_ENABLED: 'true'
          ENABLE_ML_PREDICTIONS: 'false'
          ENABLE_SENTIMENT_ANALYSIS: 'false'
          NOTIFICATION_TEST_MODE: live
          TEST_TELEGRAM_BOT_TOKEN: ${{ secrets.TEST_TELEGRAM_BOT_TOKEN }}
          TEST_TELEGRAM_CHAT_ID: ${{ secrets.TEST_TELEGRAM_CHAT_ID }}
        run: |
          : > .env  # D-06 — empty .env at bootstrap entry
          bash bootstrap.sh

      - name: Run integration suite
        env:
          MARKET_DATA_SOURCE: tape
          NOTIFICATION_TEST_MODE: live
          TEST_TELEGRAM_BOT_TOKEN: ${{ secrets.TEST_TELEGRAM_BOT_TOKEN }}
          TEST_TELEGRAM_CHAT_ID: ${{ secrets.TEST_TELEGRAM_CHAT_ID }}
        run: |
          pytest tests/integration -v --tb=short

      - name: Anti-mock guard (D-12)
        if: github.event_name == 'pull_request'
        run: |
          # Compare PR HEAD against main to enforce D-12 — refuse mocks/skips/xfails/threshold-lowering inside tests/.
          # NOTE: gated to pull_request events. Direct pushes bypass this. Operator MUST
          # configure GitHub branch protection on main/master to require PRs (see plan
          # `<verification>` block).
          git fetch origin main
          git diff origin/main..HEAD -- 'tests/' | bash scripts/iter-fix-check-diff.sh

      - name: Collect docker logs
        if: always()
        run: |
          mkdir -p logs
          docker compose -f docker-compose.unified.yml logs > logs/integration-logs.txt 2>&1 || true

      - name: Upload logs
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: integration-logs
          path: logs/integration-logs.txt
          retention-days: 14

      - name: Tear down
        if: always()
        run: docker compose -f docker-compose.unified.yml down -v || true
```

(b) Workflow never echoes `$TEST_TELEGRAM_BOT_TOKEN` (acceptance criterion `! grep -E "echo.*TEST_TELEGRAM"`). (c) Token is passed via `env:` not `run:` command line. **Operator-action note (Warning #1 — branch protection MUST be configured for the anti-mock guard to be effective):**

The anti-mock guard runs only on `pull_request` events. Direct pushes to `main`/`master` bypass it. To close the gap, the operator MUST configure GitHub branch protection:

1. Navigate to GitHub repo → Settings → Branches → Branch protection rules.
2. Add a rule for `main` (and `master` if used) with these settings enabled:
   - "Require a pull request before merging" — checked
   - "Require status checks to pass before merging" — checked, and add `Integration Suite (Phase 2)` to the required checks list
   - "Do not allow bypassing the above settings" — checked (or "Restrict who can push" set to nobody)
   - "Require linear history" — recommended
3. After the rule is in place, direct pushes to main/master are refused at the GitHub side; the only path to those branches is via PR, which triggers the anti-mock guard.

Without this configuration, an operator can push a test-muted diff directly to main and the guard never runs. The plan files this as an operator action because it cannot be enforced from code in this repo.
</verification>
