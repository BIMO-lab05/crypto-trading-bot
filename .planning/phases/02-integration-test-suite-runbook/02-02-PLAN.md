Output: New `POST /api/v1/admin/force-signal` route on trading-engine (port 8005), an `admin_force_signal_router` mounted in main.py, and tests asserting 200 / 403 (LIVE) / 422 (validation).

   ```python
   # =============================================================================
   # FORCE-SIGNAL ADMIN ENDPOINT (CD-04, Phase 2 INFRA-01)
   # =============================================================================
   # Test-only entry point for the integration suite. Inject a deterministic
   # synthetic signal that emits the same RabbitMQ event a real strategy would.
   # Gated to TRADING_MODE != LIVE — refusing in LIVE mode is the security boundary.
   #
   # Auth note: trading-engine has no auth middleware; admin routes are protected
   # upstream at the api-gateway. Phase 2 host-side suite talks directly to :8005,
   # but TRADING_MODE gate prevents any non-test invocation in real-money mode.

   admin_force_signal_router = APIRouter(
       prefix="/api/v1/admin/force-signal",
       tags=["Admin: Force Signal"],
   )


   @admin_force_signal_router.post("", summary="Force a synthetic signal for integration tests")
   async def force_signal(request: SignalSubmissionRequest) -> Dict[str, Any]:
       """Inject a synthetic signal — used by Phase 2 integration suite per CD-04.

       Refuses in LIVE mode (HIGH severity threat — must never inject in real-money mode).
       """
       settings = get_settings()
       if settings.trading_mode == "LIVE":
           raise HTTPException(
               status_code=403,
               detail="force-signal disabled when TRADING_MODE=LIVE",
           )

       orchestrator = get_strategy_orchestrator()
       try:
           direction = SignalDirection(request.direction)
       except ValueError:
           direction = SignalDirection.FLAT

       signal = StrategySignal(
           signal_id=f"sig_{datetime.now(timezone.utc).strftime('%Y%m%d_%H%M%S')}_{uuid.uuid4().hex[:8]}",
           strategy_id=request.strategy_id,
           symbol=request.symbol,
           timestamp=datetime.now(timezone.utc),
           direction=direction,
           action=request.action,
           strength=request.strength,
           confidence=request.confidence,
           entry_price=Decimal(str(request.entry_price)) if request.entry_price else None,
           stop_loss_pct=request.stop_loss_pct,
           take_profit_pct=request.take_profit_pct,
           position_size_pct=request.position_size_pct,
           urgency=request.urgency,
           reasoning=request.reasoning,
       )

       # Loud, grep-able state-transition log line for CI audits and 02-09 anti-mock guard.
       # Sanitize: log only the safe scalar fields, never raw `reasoning` (free-form text).
       logger.warning(
           "FORCE_SIGNAL: strategy_id=%s symbol=%s action=%s direction=%s",
           request.strategy_id, request.symbol, request.action, request.direction,
       )

       result = orchestrator.submit_signal(signal)
       return {
           "success": result.get("accepted", False),
           "signal_id": signal.signal_id,
           **result,
           "timestamp": datetime.now(timezone.utc).isoformat(),
       }
   ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| docker network → trading-engine :8005 | Test fixtures and container-internal callers reach admin endpoint |
| operator env → settings.trading_mode | Mode flag controls LIVE refusal |
| HTTP body → SignalSubmissionRequest | Untrusted scalar inputs enter the signal pipeline |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | E (elevation) | force-signal in LIVE mode | mitigate | HTTP 403 refusal when `settings.trading_mode == "LIVE"`. Gate runs BEFORE orchestrator call. Verified by Task 1 Test 2. |
| T-02-02-02 | T (tampering) | synthetic signal injected into real-money pipeline | mitigate | Same gate as T-02-02-01. Plus: project's three-flag LIVE checklist (`PAPER_TRADING_MODE=false`, `TRADING_MODE=LIVE`, `LIVE_TRADING_ACK=I_UNDERSTAND_REAL_MONEY`) — all three must be set, and even then this endpoint refuses. |
| T-02-02-03 | I (info disclosure / log injection) | request.reasoning is free-form text | mitigate | logger.warning explicitly excludes `request.reasoning` (free-form). Only controlled scalars logged: strategy_id, symbol, action, direction. Verified by acceptance criterion `! grep "request.reasoning" .. | grep logger`. |
| T-02-02-04 | D (DoS) | rate-limit on admin endpoint | accept | trading-engine does not have slowapi installed; per-test cadence (≤ 10 calls/test run) does not warrant adding the dep. Network is docker-internal in test contexts. If LIVE mode were ever enabled, the gate refuses BEFORE orchestrator call (no DoS vector through orchestrator). |
| T-02-02-05 | R (repudiation) | unaudited admin call | mitigate | Single log line `FORCE_SIGNAL: strategy_id=<id> symbol=<sym> action=<a> direction=<d>` written at WARNING level. CI log audit (02-09) and RUNBOOK triage (02-07) rely on this. |
| T-02-02-06 | S (spoofing) | no-auth network exposure | accept | Consistent with project pattern — trading-engine has no auth middleware. The TRADING_MODE gate is the security boundary. Any LIVE deploy that exposes :8005 outside docker network is an operator/deploy error tracked separately. |
</threat_model>
