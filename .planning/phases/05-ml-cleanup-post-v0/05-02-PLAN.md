Available knobs in the YAML schema (from `example_tournament.yaml`):
- `tournament_id`, `seed`, `symbols`, `intervals`, `target_modes`
- `default_resource_caps` (mem_limit, cpus, wallclock_timeout_seconds)
- `max_experiments` (Cartesian-grid hard cap)
- `architectures` (gru / lstm / transformer / tcn) with per-architecture grids: `units`, `dropout`, `lr`, `batch`, `lookback`, `horizon`, `n_heads`, `n_blocks`, `kernel_size`, `dilation_base`, `ff_dim_multiplier`, `resource_caps`

What the harness measures (from Phase 3 leaderboard schema): `r2_returns`, `dir_acc_corrected`, `oos_sharpe`, `psr`, `dsr`, `cpcv_dsr`, `train_seconds`, `git_sha`.

What Phase 4 adds on top (after `tournament run` completes): `tournament open-pr <tid>` builds per-symbol top-3-by-DSR ensembles + bootstrap p-values vs persistence baseline, writes `<tid>.{ensemble,significance,leaderboard}.{json,md}` next to the snapshot.

The five candidate experiments (REQUIREMENTS.md MLCL-02):
1. **Different horizon** — Phase 3 grid uses `horizon: [5]` (5 bars). Variants: `horizon: [1, 24, 96]` for sub-hour / multi-day predictions.
2. **Classification head** — predict `sign(next_return)` instead of regression. Requires `target_mode: "binary_direction"` (not in current loader's enum — would need a new mode, larger change).
3. **XGBoost control** — non-deep-learning baseline. Requires a new `architectures.xgboost` registry entry (not currently supported).
4. **Cross-sectional features** — feed a panel of related symbols' lagged returns to predict one symbol. Requires a multi-symbol input pipeline (not in current per-symbol pipeline).
5. **Sentiment-as-filter** — gate trades on sentiment score. Requires sentiment-analysis-service integration (the service is parked per CLAUDE.md feature flags `ENABLE_SENTIMENT_ANALYSIS=false`).

Architectural cost ranking (lowest → highest effort):
- **Different horizon** — pure YAML edit, zero new code. ~minutes to author + train time.
- **Classification head** — new target_mode + new metric mapping. ~hours.
- **Cross-sectional features** — new pipeline + new model interface. ~days.
- **XGBoost control** — new architecture builder + new hyperparameter grid + scikit-learn integration. ~days.
- **Sentiment-as-filter** — un-park sentiment service + new signal merge layer. ~days+, conflicts with current ENABLE_SENTIMENT_ANALYSIS=false posture.

Per ADR-style reasoning the planner has surfaced — but the executor MUST write 05-02-DECISION.md with their own analysis, citing all five options and the recommendation. The recommendation should weight: (a) information gain from the result, (b) implementation cost in this plan's context budget, (c) reversibility of the choice.
