**The two options:**

**Option A — Rewrite to use CoreAggregator:**
- Import `CoreAggregator` and `Settings`
- Replace `HybridStrategyRouter` invocation with `CoreAggregator(settings).aggregate(...)` call
- Backtest's per-bar loop feeds OHLCV slices into the aggregator
- Output PnL is now comparable to live trading
- **Cost:** medium-to-high. CoreAggregator's interface expects live indicator state, including potentially: realised vol estimator state (vol_targeting), funding rate cache (funding_gate), maker quote queue (maker_orders), historical signal voter state. Replicating these in the backtest harness is real work. The current `HybridStrategyRouter` was chosen because it's stateless per-bar; CoreAggregator may not be.
- **Value:** high. Backtest output finally predicts live behaviour. The whole point of a backtest harness.
- **Risk:** medium. May discover that CoreAggregator can't be made to work in offline backtest mode at all (e.g., funding rate gate requires live API). In which case the docstring still needs sharpening AND a sub-divergence call-out.

**Option B — Document the divergence permanently + runtime warning:**
- Replace the punt language at lines 26-27 with explicit permanence: "**This script intentionally uses HybridStrategyRouter, not the live CoreAggregator. The divergence is documented and will not be fixed; treat output as strategy-regime-characterisation only, not as a forecast of live PnL.** See ADR-012 for rationale."
- Add a runtime warning at the top of `main()` (or whatever the script entry is): `logger.warning("RUN_EXTENDED_BACKTEST: signal logic diverges from live CoreAggregator — do NOT treat output as live-PnL forecast. See ADR-012.")`
- Optional: add a `--i-understand-this-is-not-live-signal-logic` CLI flag the script refuses to run without (forcing the operator to acknowledge in argv).
- **Cost:** low. ~30 lines of edit + a test.
- **Value:** medium. Doesn't fix the divergence — just makes it loud.
- **Risk:** low.

**Project rules (load-bearing for the choice):**
- CLAUDE.md "Verification standards" says: "No declare features 'working end-to-end' on curl/HTTP 200 alone." Backtest output without live-aggregator alignment violates this spirit by producing numbers that don't predict live behaviour.
- PROJECT.md "Core value: every 'edge' claim must be backed by DSR/CPCV evidence on returns." Backtest is part of the evidence chain; if it diverges silently, edge claims based on it are unfounded.
- The Phase 3+4 tournament harness exists specifically for honest evaluation; that's the operator's path for actual edge measurement. `run_extended_backtest.py` is a STRATEGY-CHARACTERISATION tool, not an EDGE-CLAIM tool.
- Given the tournament harness exists for the edge-claim path, **option B is the planner's recommendation** — let the tournament be the honest path, let `run_extended_backtest.py` be the strategy regime tool with explicit divergence. Option A is a high-cost rewrite that duplicates what the tournament harness already does honestly.
