<objective>
Close P21-3: make the multi-timeframe demote-to-HOLD decision gate **all three** ensemble legs, not just `multi_indicator`. Land the phase's threshold-lock guard first so every subsequent gating change is measured against a fixed floor.

Purpose: `consolidate_mtf_confidence` demotes a consensus to HOLD when no timeframe's gated action agrees. `signal_aggregator.py:1133` already writes that demoted action onto `primary_signal.action`, and the `multi_indicator` leg honors it via its `action != HOLD and confidence > 0` guard at `multi_strategy_ensemble.py:314-317`. The `simple_rsi` and `mean_reversion` legs never read `.action` at all (`:303`, `:336`), so they trade straight past a demotion the system already made.

**This is a wiring fix, not threshold tuning.** No threshold value changes anywhere in this plan.

## Narrow versus broad, and why narrow wins

`action == HOLD` arrives from four distinct upstream causes: MTF consensus demoted (`signal_aggregator.py:71-78` — this is P21-3), a raw MTF consensus that was genuinely HOLD, the regime hard-block at `:1189`, and a per-timeframe requirements gate resolving HOLD upstream in `aggregator_core`. Gating on bare `aggregator_signal.action == SignalAction.HOLD` is simpler and needs no new metadata key, but it also suppresses the regime hard-block and the upstream-requirements cases — **more than CONTEXT authorizes**.

Take the narrow route: one new metadata key. It is necessary because `metadata["multi_timeframe"]["consensus_action"]` at `:1137` stores `mtf_analysis.consensus_action`, the **pre**-demotion value, so demotion is currently undetectable downstream. Record the regime hard-block case as a candidate follow-up rather than silently widening scope.

`P21-3` in the `requirements` field is an audit-defect ID from `.planning/audits/2026-08-26-ta-signal-path-audit.md`, in scope per CONTEXT's authority clause.
</objective>
