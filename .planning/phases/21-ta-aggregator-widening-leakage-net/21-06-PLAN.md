**P21-2 — leg source-diversity guard.** Agreement counting must not present single-source information as multi-leg agreement. `simple_rsi` reads exactly one indicator (`simple_rsi_strategy.py:51`), so it is structurally a MOMENTUM-only leg. Mirror the category-diversity idea `CoreAggregator` already applies to its voters. Fix it as **wiring correctness**, not threshold tuning.

**Rejection telemetry — the choice, made explicitly.** 21-RESEARCH.md Pitfall 5 requires choosing between (a) a structured rejection reason wired into the funnel and (b) parsing log lines, and requires the choice be stated rather than left implicit. **This plan takes (a).** Rationale: `generate_signal` signals every rejection by returning `None`, and `auto_trader._check_and_trade_ensemble` records that as one funnel gate with a fixed `reason="ensemble_returned_hold"` and a `detail` naming only two causes. After Plan 21-05 and this plan there are **four** causes — weighted score, leg count, diversity block, MTF demotion — collapsing into one bucket whose detail string is factually wrong for two of them. Shipping a wrong log string is the same class of defect this phase exists to remove, and the Plan 21-09 ablation cannot attribute a delta it cannot separate.

## The framing a reviewer will challenge — answer it in the code

`mean_reversion` cannot fire on RSI alone: `MIN_INDICATORS_ALIGNED = 2` (`mean_reversion_strategy.py:91`) requires a Bollinger or SMA co-signal. So the real concentration case reduces to **`simple_rsi` firing alone**, and a guard that blocks it is, in the single-leg case, functionally equivalent to `MIN_AGREEING_LEGS = 2` — while leaving the constant at `1`, which is what the lock literally requires.

The category framing is nonetheless the defensible one, and it is **materially different** from a leg count. The two rules diverge exactly where it matters:

| Case | Categories | Diversity guard | `MIN_AGREEING_LEGS = 2` |
|---|---|---|---|
| `simple_rsi` alone | {MOMENTUM} | block | block |
| `simple_rsi` + `mean_reversion` | {MOMENTUM} union {MOMENTUM, VOLATILITY} = 2 | pass | pass |
| `multi_indicator` alone | >= 2 by construction | **pass** | **block** |

`multi_indicator` is the leg carrying the full nine-voter gate stack and it has already cleared `CoreAggregator`'s own two-category gate. Blocking it would be a serious regression on the strongest leg. Put this table's conclusion in the code comment so the guard is not read as a smuggled threshold change.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| leg outputs -> agreement counting -> trade admission | Two legs reading the same RSI print can present as independent confirmation; agreement is the last gate before sizing |
| ensemble rejection -> funnel telemetry -> operator interpretation | A wrong `detail` string is how an operator concludes the wrong thing about why trading stopped |
| locked threshold constants -> effective gate | An effective-gate change that leaves the constants untouched passes a naive constants-only review |
