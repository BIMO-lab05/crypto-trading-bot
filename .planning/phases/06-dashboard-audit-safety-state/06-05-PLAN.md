<!-- TileState API contract (06-PATTERNS.md lines 82-96 + D-12, D-13, D-14, D-15) -->
TileState props:
  - query: React Query result {isLoading, isFetching, isError, isSuccess, error, data, refetch}
  - isEmpty?: (data) => boolean        // default: data == null || data?.length === 0
  - lastUpdatedAt?: string | number     // ISO ts or epoch ms; drives stale badge
  - staleAfterMs?: number               // per-tile threshold; defaults to STALE_THRESHOLDS_MS[thresholdKey] || STALE_THRESHOLDS_MS.default
  - thresholdKey?: keyof STALE_THRESHOLDS_MS  // alternative to staleAfterMs
  - title: string                       // shown in error message
  - forceStale?: boolean                // LABELED_STALE verdict tiles set this true
  - children: React.ReactNode           // the actual tile body, rendered when not loading/empty/error

<!-- Precedence rule (F-05 — D-13 intent: errors are loud) -->
Order of checks in the component body:
  1. query.isError → Failed (...) + Retry button (children NOT rendered)
  2. query.isLoading && !query.data → skeleton (children NOT rendered)
  3. query.isSuccess && isEmpty(query.data) → "No data yet" (children NOT rendered)
  4. (forceStale || isStale(lastUpdatedAt, staleAfterMs)) && query.isSuccess → children + stale-overlay badge
  5. otherwise → children only (success-non-empty steady state)
forceStale flips ONLY between branches 4 and 5; it does NOT bypass branches 1-3.
