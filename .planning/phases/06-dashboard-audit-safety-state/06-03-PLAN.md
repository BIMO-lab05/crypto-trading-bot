## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-03-01 | Tampering | VITE_WS_URL env var | MEDIUM | mitigate | If an attacker can set VITE_WS_URL at build time, the WS client points at an attacker host — proxy/MITM risk. Mitigation: same-origin enforcement via the production branch (non-DEV path uses `window.location.host` regardless of env); env var is consulted ONLY in `import.meta.env.DEV`. Operators MUST verify build target before shipping. Documented in vite.config.js doc-block extension. |
| T-06-03-02 | Spoofing | grep gate bypassed via clever encoding | LOW | accept | A determined developer can concatenate `"http://" + "localhost:8000"` to evade the literal-match grep. Out of scope; the gate is a regression guard against accidental hardcoding, not a sandbox. |
| T-06-03-03 | Information Disclosure | VITE_* env vars bundled into client JS | LOW | accept | Vite by convention exposes VITE_*-prefixed env vars to client code; non-VITE_* vars never bundle. The two vars here (VITE_API_BASE_URL, VITE_WS_URL) are intentionally exposed and contain no secrets. |

No HIGH-severity threats. Production-branch same-origin enforcement is the load-bearing mitigation for T-06-03-01.
