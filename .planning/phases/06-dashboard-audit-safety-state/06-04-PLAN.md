## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| /api/config/safety-state response -> React Query cache -> UI render | Single 5s poll drives all 3 cells + viewport border |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-04-01 | Spoofing | stale poll showing PAPER while engine is LIVE | MEDIUM | mitigate | Backend response (Plan 6-02) is the single source of truth; viewport border + pill both derive from `safety.trading_mode` in the SAME poll, so they cannot disagree with each other. 5s staleTime is the upper bound on staleness. `last_updated_at` will be consumed by `<TileState/>` in Plan 6-05 to render a stale badge if backend stops updating. |
| T-06-04-02 | Tampering | env var swap on api-gateway (covered upstream) | MEDIUM | mitigate | Mitigated at the api-gateway env-read boundary in Plan 6-02 (same threat model entry T-06-02-04). UI faithfully renders what the gateway reports. |
| T-06-04-03 | Information Disclosure | trading_mode in client JS | LOW | accept | Already accepted in Plan 6-02 (T-06-02-01). UI is one consumer; not a new disclosure boundary. |
| T-06-04-04 | Denial of Service | unbounded refetch on safety-state | LOW | accept | React Query refetchInterval is bounded at 5000ms; retry capped at 2 with 1000ms delay; cannot fan out arbitrary requests. |
| T-06-04-05 | Spoofing | XSS injects fake trading_mode pill | LOW | mitigate | React JSX escapes string values by default; trading_mode is rendered as a text child `{value}`, not via unsafe HTML-injection APIs. Same XSS baseline as the rest of the dashboard; no new sink added in this plan. |

No HIGH-severity threats. The most consequential threat (T-06-04-01 stale-poll spoofing) is mitigated by single-source-of-truth + Plan 6-05's stale badge.
</threat_model>
