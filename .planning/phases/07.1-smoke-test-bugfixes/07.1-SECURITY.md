## Summary

Retroactive STRIDE review of Phase 07.1's three bugfixes. BUG-1 (`tests/integration/test_dashboard_smoke.py` `.first` qualifier) and BUG-2 (`06-TILE-AUDIT.json` `data_testid_scope: descendant`) are test/config-only — minimal threat surface, single accepted-risk each. BUG-3 (`services/api-gateway/app/main.py:2407-2473` catch-all reverse-proxy) introduces a new outbound HTTP path from api-gateway to the frontend nginx container governed by the `FRONTEND_UPSTREAM` env var; this is the only non-trivial surface and is enumerated in detail below. Operator-controlled env-var trust + internal docker-network scoping are the two load-bearing assumptions; both are explicitly accepted as solo-operator honour-system risks.

No new auth surface, no secrets, no DB writes; the proxy is GET-only and refuses gateway-owned paths via a defense-in-depth bypass list.

### BUG-3 (api-gateway reverse-proxy) — interesting surface

| Threat ID | Category | Disposition | Status | Evidence |
|-----------|----------|-------------|--------|----------|
| T-07.1-03-01 | Spoofing / SSRF via `FRONTEND_UPSTREAM` env | accept | closed | `services/api-gateway/app/main.py:2424` reads `os.environ.get("FRONTEND_UPSTREAM", "http://frontend:80")` at request time. Threat: attacker who controls the env can proxy arbitrary URLs through the gateway. Mitigation: env vars are operator-controlled at compose time (`docker-compose.unified.yml:288-299`); no API surface mutates env; safe default `http://frontend:80` resolves only inside the docker bridge network. Threat reduces to "operator must not paste a malicious URL into their own `.env`" — same trust class as `BYBIT_API_KEY`. AR-07.1-01. |
| T-07.1-03-02 | Information disclosure / open relay | mitigate | closed | Catch-all is GET-only (`methods=["GET"]` at L2407); no body forwarding, no method tunneling. Defense-in-depth bypass list at L2419-2422 raises `HTTPException(404)` when `normalized in _GATEWAY_OWNED_EXACT` or path starts with `_GATEWAY_OWNED_PREFIXES = ("api/",)` (L2392-2404) — fails closed before any upstream call, so even a hostile upstream cannot exfiltrate gateway-owned `/api/*` JSON via the proxy path. Test `test_reverse_proxy_bypasses_api_paths` at `test_reverse_proxy.py:100-117` pins the constants. |
| T-07.1-03-03 | Tampering / Content-Encoding mismatch (browser ERR_CONTENT_DECODING_FAILED) | mitigate | closed | `main.py:2466` strips `content-encoding` from upstream response headers because `httpx` auto-decompresses `upstream_resp.content` (L2469); inline comment L2455-2457 documents the rationale. Fix landed at commit `2a673d9` after live verification surfaced the failure. Live `curl :8000/` → `content-type: text/html` ✓ confirms the body+headers are now coherent. |
| T-07.1-03-04 | Path traversal via proxied URL | mitigate | closed | `main.py:2418` `normalized = full_path.lstrip("/")` then constructed as `f"{upstream}/{normalized}"` (L2426); no `..` collapse needed because the upstream is nginx serving a static SPA bundle (filesystem-rooted at `/usr/share/nginx/html`) — nginx itself rejects `..` traversal. FastAPI's `{full_path:path}` converter does not URL-decode beyond standard percent-decoding, so encoded traversal (`%2e%2e`) is forwarded as-is for nginx to handle. No filesystem read in the gateway process. |
| T-07.1-03-05 | DoS via connection-pool exhaustion | accept | closed | `main.py:2439` `async with httpx.AsyncClient(timeout=10.0) as client` opens a fresh client per request — no module-level pool. Documented as `failure_mode` in `07.1-01-PLAN.md` and re-flagged in `07.1-VALIDATION.md` §4 item 4 ("acceptable for the local smoke consumer; would need a module-level reusable client for production load"). 10s timeout caps per-request fd hold; gateway is behind operator-only ingress in current deployment. AR-07.1-02. |
| T-07.1-03-06 | Header injection / Host smuggling | mitigate | closed | `main.py:2429-2436` builds `forward_headers` by filtering hop-by-hop headers (per RFC 7230 §6.1 set at L2376-2387) AND explicitly drops the inbound `Host` header (L2435 `and k.lower() != "host"`) so httpx sets the correct upstream host; this prevents Host-header smuggling against a virtual-host-routed upstream. Test `test_hop_by_hop_set_matches_rfc7230` at `test_reverse_proxy.py:145-159` pins the strip set verbatim against RFC 7230. |
| T-07.1-03-07 | Cookie leakage to upstream | accept | closed | `main.py:2429-2436` does NOT explicitly strip `Cookie` (it is not a hop-by-hop header). Frontend nginx at `http://frontend:80` is internal-only (docker bridge), serves only static SPA assets, and does not log cookies. The gateway's own auth cookies (`HTTPBearer`) are still forwarded but cause no issue because nginx ignores them. Threat: if `FRONTEND_UPSTREAM` is ever flipped to an external host, cookies would leak. Tied to T-07.1-03-01 trust assumption. AR-07.1-03. |
| T-07.1-03-08 | Caching layer bypass / cache poisoning | mitigate | closed | Catch-all is GET-only and stateless from the gateway's perspective (no gateway-side cache); upstream `Cache-Control` / `ETag` / CSP headers pass through unmodified per L2458-2467 (only hop-by-hop + content-length + content-encoding stripped). The upstream nginx owns its cache headers; the gateway does not interpose. Browser cache key includes the gateway origin (`localhost:8000`), so no cross-origin cache pollution risk against the frontend container's direct ingress (port 3000) — they share no origin. |

## Operator Notes

- The reverse-proxy is the only meaningful new attack surface in this phase. Three load-bearing assumptions: (1) `FRONTEND_UPSTREAM` is operator-controlled at compose time; (2) the upstream resolves only inside the docker bridge network; (3) the gateway's deployment posture is operator-only ingress (no public internet exposure). If any of these change, revisit AR-07.1-01 / AR-07.1-02 / AR-07.1-03.
- BUG-1 + BUG-2 are test/config diff only; their "threats" are framed as test-suite integrity (cannot silently pass on broken assumptions). The smoke's strict-mode failure mode is loud, and the audit JSON is walked directly by the smoke so config drift surfaces in CI.
- 12 pre-existing semgrep WARNINGs on `docker-compose.unified.yml` (postgres / timescaledb / redis / rabbitmq / prometheus / grafana container hardening + docker.sock surface) remain deferred per `deferred-items.md`; tracked for a future security-hardening plan.
