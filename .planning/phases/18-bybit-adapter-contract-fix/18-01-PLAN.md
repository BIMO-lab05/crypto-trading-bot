| `get_ticker`         | :1003 | `/api/v1/market/tickers`   | `/api/v1/market/ticker`      | `main.py:739` `@app.get`  |

**Mapping rationale for the `/order/realtime` fork (key call):**
Connector replaced single `/order/realtime` with two routes: `/order/open` (live open orders) and `/order/history` (closed/cancelled paginated). D-04 forbids adding new adapter helpers. Both existing adapter consumers semantically want OPEN orders only:
- `get_open_orders()` literally returns "open orders" — `/order/open` is the natural target.
- `get_order_status(symbol, order_id)` is consumed only by the LIVE path (`live_trading.py`) to poll the status of an order the adapter just submitted (it's about to be open or filled-from-open). The current `OrderNotFoundError` on empty `list` already matches "checking an order that has already moved to history returns nothing." Phase 19 (RECON-01) is the place that will own the open+history reconcile sweep; until then, `get_order_status` reads from `/order/open` and surfaces `OrderNotFoundError` on the closed-order case — same behavior as today. This honors D-04 ("any new connector routes stay unimplemented on the adapter side until a future phase requires them") and keeps `/api/v1/order/history` UNCONSUMED by the adapter.

Purpose: closes the BC-FIX-01 contract gap that makes LIVE trading dead-on-arrival. Paper mode bypasses `bybit_adapter` entirely (per D-15 + `live_trading.py:290-360` audit), so this is latent-in-paper / fatal-on-LIVE-flip — the same low-runtime-risk profile CONTEXT.md documents.

Output: 1 modified file, 5 string replacements, 0 line-count delta (one-for-one string swaps).
