## Decisions Made

- **Schema closed for extension after Plan 11.1-01.** Wave 2 plans (11.1-02..06) must consume read-only — they can import `write_evidence` and `STATUS_*`, but MUST NOT modify `_schema.json` or `_common.py`. This is a hard contract — any drift surfaces in code review.
- **`schema_version` and `timestamp` are helper-managed, not caller-managed.** Removing both from the `write_evidence()` signature prevents accidental drift across harnesses (each harness would otherwise pass its own `datetime.now()` and risk timezone or format inconsistency).
- **Collision (`extra` key overlaps a required field) raises `ValueError`, not `ValidationError`.** Distinguishes "caller used the API wrong" from "data is shaped wrong" — `ValidationError` is reserved for actual schema drift (bad status enum, bad `liveclose_id`).
- **`argparse.BooleanOptionalAction` with `required=True`.** Operators must explicitly state `--human-needed` or `--no-human-needed` at the CLI surface; no silent default flips a critical wall-clock flag.
- **Pinned argparse `--status` to free-form string (not `choices=...`).** This was intentional: the schema is the single source of truth for the enum, so a `BOGUS` status surfaces as a `jsonschema.ValidationError` (with the helpful schema-driven error message listing the four valid values), not an `argparse.error` (which would only echo argparse's own usage).
