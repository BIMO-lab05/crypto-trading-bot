# Gap Audit Findings — 2026-08-19

Spec: docs/superpowers/specs/2026-08-19-gap-audit-design.md. Prior verdicts cited, not re-derived.

## Verdict

**CONFIRMED, not overturned: economic non-viability + statistical illusion.** This audit was scoped to answer one question — does a hidden implementation defect in the backtest engine make the prior REJECT verdict untrustworthy? The answer is no. Every check capable of falsifying the prior verdict (determinism, reconciliation, random-walk baseline, sign/shift check) came back clean, and the defects this audit did find all bias historical P&L *upward* (more optimistic than reality), which strengthens rather than weakens the REJECT.

Three strongest pieces of evidence:

1. **Prior killtests stand unchallenged.** Phase-0 audit (2026-08-04): H4 REJECT, 49.07% directional accuracy (chance level), DSR 0.0, gross edge 4.88bp/trade vs 21–31bp round-trip cost. Profit-path repair (2026-08-12) fixed 16 money-path defects without producing an edge. Edge batteries (2026-08-17/18) delivered 9× REJECT across the top-30 perp universe. This audit re-derives none of that — it only checks whether the *measuring instrument* (the backtest engine) was lying.
2. **The instrument is not lying in the direction that would matter.** `gap_determinism.py` → `determinism=PASS` (identical seed/config reproduces identical results — no hidden nondeterminism inflating apparent edge). `gap_reconcile.py` → `reconcile=PASS residual=-0.000000` (equity curve reconciles against trade-by-trade P&L to the cent — no phantom capital). `gap_randomwalk.py` → `randomwalk=PASS mean_pnl=0.3089 positive_seeds=12/20` on a corrected drift-free-in-price generator (a random-entry strategy run through the same engine does not show consistent positive expectancy at the ≥15/20 threshold the check treats as a red flag; see limitations below on the disjunctive gate and single-strategy coverage). `gap_signcheck.py` → `signcheck=no_edge_either_way` (inverting every signal doesn't turn the loss into a win, so there's no sign/shift bug masking a real edge).
3. **The genuine defects found (Invariant A same-bar fill, gap-through stop fills) make historical backtests look *better* than live execution would; the absent-short-funding defect is a separate, small, direction-uncertain bias.** Invariant A: `invariant_a=FAIL` — the engine fills a signal generated from bar t's close at bar t's close in the same iteration (`backtesting/backtest_engine.py:282`, `:303`, `:308`), i.e. zero-lag fills that no real order routing can achieve. This is unambiguously optimistic. Funding: `funding_short=not_charged` — shorts never pay funding (`backtesting/backtest_engine.py:236` gates the deduction on `OrderType.BUY` only). Per the engine's own documented convention (`:161-162`: positive rate ⇒ longs pay), a short position would normally *receive* funding when omitted, not save a cost it should have paid — so this omission is more likely a small **pessimistic** bias (shorts look slightly worse than reality), not optimistic. Magnitude is negligible either way (~$0.001/interval on a ~$10 notional). The load-bearing "defects strengthen the REJECT" argument rests on defect #1 (same-bar fill) and defect #4 (gap-through stops), both unambiguously optimistic, not on funding.

Net: no hidden defect rescues any strategy. Fixing same-bar fill lag and gap-through stop realism would make every existing Sharpe number in the CLAUDE.md table *more* negative; fixing the short-funding omission would have a negligible, and possibly opposite-signed, effect.

## What is NOT broken

- **Determinism.** `gap_determinism.py` → `determinism=PASS`. Identical seed/config produces byte-identical results across repeated runs — no hidden randomness (dict ordering, floating-point nondeterminism, uninitialized state) is inflating or varying reported performance.
- **Equity reconciliation.** `gap_reconcile.py` → `reconcile=PASS residual=-0.000000`. The engine's reported equity curve reconciles to the cent against an independent trade-by-trade P&L replay — no phantom capital creation/destruction, no double-counted fees or fills.
- **Random-walk baseline does not show consistent positive expectancy on noise.** `gap_randomwalk.py` → `randomwalk=PASS mean_pnl=0.3089 positive_seeds=12/20`. The generator was corrected in this fix round to be drift-free in *price* space (`steps = rng.normal(-0.5*sigma**2, sigma, n)`, the Itô correction — the prior `rng.normal(0.0, sigma, n)` was zero-drift only in log space, which is +9.8%/year drift in price space and made the earlier `mean_pnl=0.2769` reading uninterpretable). Re-run on the corrected generator: mean P&L is still slightly positive and 12/20 seeds are positive. The script's actual gate is `mean_pnl <= 0 or positive < 15`, a disjunction — it passes on the `positive < 15` branch, not because the mean is at or below zero. This is weaker evidence of engine cleanliness than a mean-centered-on-zero result would be, though 12/20 is well short of the ≥15/20 threshold the gate treats as a red flag. Caveats: only 1 strategy (`baseline_strategy`) × 20 seeds was run, not the ≥3 strategies × ≥20 seeds the spec calls for (see limitation below), and low trade count per seed (~4 trades/seed) limits statistical power to detect a *small* leak; this rules out gross leakage, not subtle ones.
- **No sign/shift bug masking a real edge.** `gap_signcheck.py` → `signcheck=no_edge_either_way base_pnl=-0.9952 inverted_pnl=-0.1016 est_costs=0.0977`. Inverting every trading signal does not turn the strategy profitable (both directions lose) — no evidence of an inverted comparison, off-by-one bar shift, or mislabeled long/short logic. (An earlier draft of this bullet also claimed a doubled-cost run moved P&L by the expected delta; no such run was executed — `2 * est_costs` in `gap_signcheck.py:28` is a decision threshold compared against the single measured run, not a second experiment. That clause has been removed; see limitation below.)
- **Realized risk stays under the configured cap.** `gap_risk_realized.py` → `risk=PASS loss_p95_pct=0.311 configured_cap_pct=10.0`. No trade in the sample realized a loss anywhere near the 10% paper cap (n=7 losers, thin-sample caveat noted in the defect table) — the risk breaker is not being silently bypassed, even though the sizing mechanism itself (defect #5) is notional rather than risk-based.
- **`rsi_divergence.py` pivot detection is not look-ahead leakage** (defect table row #6) — the apparent forward-index access is bounded within the already-available window, not past the live bar.
- **`resample()` usage flagged by the leakage grep is safe.** `gap_leakage_grep.py` → 11 total static hits; the `resample_calls=1` subset was manually verified in Task 2 to not introduce look-ahead (aggregation boundary aligns with, not ahead of, decision time).

## Limitations of this audit's tooling

- **`gap_randomwalk.py` covers 1 strategy, not the spec's ≥3.** Spec §3 item 5 asks for ≥3 existing strategies × ≥20 seeds; this audit ran only `baseline_strategy` × 20 seeds. The PASS gate is also disjunctive (`mean_pnl <= 0 or positive < 15`), so it does not require the mean to be at or below zero — a positive mean can still pass. Both are narrower than spec. Widen before treating a future run of this script as conclusive, and before promoting it to a regression test.
- **`gap_determinism.py` compares an 8-field rounded summary, not the full trade list or equity curve.** `result_summary()` reduces a run to eight scalars (six rounded to 6 dp). A reordered trade ledger, a divergent equity curve, or sub-1e-6 float drift would all still pass. Before promoting this script to `tests/` as a regression test, widen the hashed/compared payload to the full trade-by-trade ledger and equity curve.
- **`gap_leakage_grep.py`'s full-series-normalizer pattern is narrow.** Spec §3 item 1 asks for "full-series normalizers (fit/mean/std over whole array)" and `fillna(method=`. The implemented pattern only matches the `StandardScaler()/MinMaxScaler().fit(` idiom; it misses the equally common `scaler = StandardScaler(); scaler.fit(X)` split form, non-sklearn normalizers, and inline `(x - x.mean()) / x.std()` over a whole series — the classic form of this leak. `fillna(method=` is not matched as its own pattern. The `full_series_norm` bucket returned zero hits in this sweep; that zero is weak evidence of absence given the narrow pattern, not confirmation the codebase is clean of this leak class.

## Open questions

1. **RESOLVED (fix round 1).** `audit/run_all.py` now builds an explicit `env` dict that prepends `REPO_ROOT` to `PYTHONPATH` and passes `cwd=REPO_ROOT` to each `subprocess.run` call, so `from audit._harness import ...` resolves regardless of the caller's shell state. Verified: `env -u PYTHONPATH python3 audit/run_all.py` from a clean shell produces all 7 real `RESULT:` lines (no `NOT_VERIFIED`/`ModuleNotFoundError`). Numbers after the fix-round-2 randomwalk drift correction: `leakage_hits=11`, `invariant_a=FAIL`, `determinism=PASS`, `reconcile=PASS residual=-0.000000`, `randomwalk=PASS mean_pnl=0.3089 positive_seeds=12/20`, `signcheck=no_edge_either_way base_pnl=-0.9952 inverted_pnl=-0.1016`, `risk=PASS loss_p95_pct=0.311`.
2. `gap_invariants.py` always exits 0 regardless of `invariant_a=FAIL` — confirmed by design (its RESULT line reports the verdict; the process return code isn't used as a pass/fail signal). `run_all.py`'s failure count is therefore only sensitive to script *crashes*, not to substantive FAIL verdicts inside a script's own RESULT line. Is this the intended contract for future `gap_*` scripts, or should invariant/defect FAILs also set a nonzero exit code so `run_all.py`'s exit-code-as-failure-count design catches them?
3. Defect #2 (shorts not charged funding) needs the actual Bybit perpetual funding sign convention confirmed before a fix is written — the proposed fix in the defect table names both possible sign conventions rather than asserting one, since this audit's scope was measurement, not repair.
4. Defect #5 (notional vs. risk-based sizing) is a naming/behavior split that predates this audit (`position_size_pct` is documented as "risk per trade" in `backtest_engine.py:169` but implemented as a notional cap at `:401-402`). Should the fix be a rename (cheap, avoids re-baselining) or a behavior change to true risk-based sizing (changes every trade's position size and thus every historical P&L figure)? This decision affects re-baselining cost significantly and should be made explicitly, not as a side effect of a "risk" defect fix.
