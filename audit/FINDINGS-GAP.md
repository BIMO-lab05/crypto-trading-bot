# Gap Audit Findings — 2026-08-19

Spec: docs/superpowers/specs/2026-08-19-gap-audit-design.md. Prior verdicts cited, not re-derived.

## Verdict

**CONFIRMED, not overturned: economic non-viability + statistical illusion.** This audit was scoped to answer one question — does a hidden implementation defect in the backtest engine make the prior REJECT verdict untrustworthy? The answer is no. Every check capable of falsifying the prior verdict (determinism, reconciliation, random-walk baseline, sign/shift check) came back clean, and the defects this audit did find all bias historical P&L *upward* (more optimistic than reality), which strengthens rather than weakens the REJECT.

Three strongest pieces of evidence:

1. **Prior killtests stand unchallenged.** Phase-0 audit (2026-08-04): H4 REJECT, 49.07% directional accuracy (chance level), DSR 0.0, gross edge 4.88bp/trade vs 21–31bp round-trip cost. Profit-path repair (2026-08-12) fixed 16 money-path defects without producing an edge. Edge batteries (2026-08-17/18) delivered 9× REJECT across the top-30 perp universe. This audit re-derives none of that — it only checks whether the *measuring instrument* (the backtest engine) was lying.
2. **The instrument is not lying in the direction that would matter.** `gap_determinism.py` → `determinism=PASS` (identical seed/config reproduces identical results — no hidden nondeterminism inflating apparent edge). `gap_reconcile.py` → `reconcile=PASS residual=-0.000000` (equity curve reconciles against trade-by-trade P&L to the cent — no phantom capital). `gap_randomwalk.py` → `randomwalk=PASS mean_pnl=0.2769 positive_seeds=10/20` (a random-entry strategy run through the same engine centers on chance, exactly as it should if the engine has no built-in look-ahead or accounting leak inflating results). `gap_signcheck.py` → `signcheck=no_edge_either_way` (inverting every signal doesn't turn the loss into a win, so there's no sign/shift bug masking a real edge).
3. **The genuine defects found (Invariant A same-bar fill, absent short funding, gap-through stop fills) all make historical backtests look *better* than live execution would, never worse.** Invariant A: `invariant_a=FAIL` — the engine fills a signal generated from bar t's close at bar t's close in the same iteration (`backtesting/backtest_engine.py:282`, `:303`, `:308`), i.e. zero-lag fills that no real order routing can achieve. Funding: `funding_short=not_charged` — shorts never pay funding (`backtesting/backtest_engine.py:236` gates the deduction on `OrderType.BUY` only), so any short-heavy backtest understates its true cost. Both push the *already-negative* Sharpe figures in the CLAUDE.md table further toward zero than reality would allow — the true picture is at least as bad, plausibly worse.

Net: no hidden defect rescues any strategy. If anything, fixing these defects (same-bar fill lag, short funding, gap-through stop realism) would make every existing Sharpe number in the CLAUDE.md table *more* negative, not less.

## Minimal reproductions

**#1 — same-bar signal→fill (HIGH).** `python3 audit/gap_invariants.py` (run via `python3 audit/run_all.py`, or standalone with `PYTHONPATH=<repo-root>`). Output includes:
```
Invariant A: FAIL
  signal bar t=100 close=118634.5 ts=2025-08-10 19:00:00
  fill price=118693.81725 entry_time=2025-08-10 19:00:00
  static cite: backtest_engine.py:282 (price=row close), :303 (signal from row t), :308 (executed same iteration)
```
The probe strategy in `audit/gap_invariants.py` forces a BUY signal at bar index 100 and shows the fill timestamp equals the signal timestamp with a price derived from the same row's close (plus slippage) — confirming zero execution lag by construction of `_run_backtest_loop`/`_open_position`.

**#2 — shorts never pay funding (HIGH).** `python3 audit/gap_reconcile.py`. Output: `reconcile=PASS residual=-0.000000 funding_short=not_charged`. Static confirmation: `backtest_engine.py:236` — `if self.current_position.order_type == OrderType.BUY and self.funding_long_pays:` is the only branch that debits `self.capital`; no `elif` branch exists for `OrderType.SELL`. A short held across an 8-bar boundary shows zero funding-related capital change in the equity curve.

## What is NOT broken

- **Determinism.** `gap_determinism.py` → `determinism=PASS`. Identical seed/config produces byte-identical results across repeated runs — no hidden randomness (dict ordering, floating-point nondeterminism, uninitialized state) is inflating or varying reported performance.
- **Equity reconciliation.** `gap_reconcile.py` → `reconcile=PASS residual=-0.000000`. The engine's reported equity curve reconciles to the cent against an independent trade-by-trade P&L replay — no phantom capital creation/destruction, no double-counted fees or fills.
- **Random-walk baseline centers on chance.** `gap_randomwalk.py` → `randomwalk=PASS mean_pnl=0.2769 positive_seeds=10/20`. A strategy with no informational edge (random entries) run through the same engine and cost model produces a near-zero, roughly symmetric outcome distribution (10/20 seeds positive) — exactly what a correctly-costed, non-leaking engine should produce. Caveat: low trade count per seed (~4 trades/seed per task-6 report) limits statistical power to detect a *small* leak; it rules out gross leakage, not subtle ones.
- **No sign/shift bug masking a real edge.** `gap_signcheck.py` → `signcheck=no_edge_either_way base_pnl=-0.9952 inverted_pnl=-0.1016 est_costs=0.0977`. Inverting every trading signal does not turn the strategy profitable (both directions lose), and doubling costs moves P&L by roughly the expected cost delta rather than something erratic — no evidence of an inverted comparison, off-by-one bar shift, or mislabeled long/short logic.
- **Realized risk stays under the configured cap.** `gap_risk_realized.py` → `risk=PASS loss_p95_pct=0.311 configured_cap_pct=10.0`. No trade in the sample realized a loss anywhere near the 10% paper cap (n=7 losers, thin-sample caveat noted in the defect table) — the risk breaker is not being silently bypassed, even though the sizing mechanism itself (defect #5) is notional rather than risk-based.
- **`rsi_divergence.py` pivot detection is not look-ahead leakage** (defect table row #6) — the apparent forward-index access is bounded within the already-available window, not past the live bar.
- **`resample()` usage flagged by the leakage grep is safe.** `gap_leakage_grep.py` → 11 total static hits; the `resample_calls=1` subset was manually verified in Task 2 to not introduce look-ahead (aggregation boundary aligns with, not ahead of, decision time).

## Open questions

1. **RESOLVED (fix round 1).** `audit/run_all.py` now builds an explicit `env` dict that prepends `REPO_ROOT` to `PYTHONPATH` and passes `cwd=REPO_ROOT` to each `subprocess.run` call, so `from audit._harness import ...` resolves regardless of the caller's shell state. Verified: `env -u PYTHONPATH python3 audit/run_all.py` from a clean shell produces all 7 real `RESULT:` lines (no `NOT_VERIFIED`/`ModuleNotFoundError`), and the numbers are identical to the prior PYTHONPATH-set run (`leakage_hits=11`, `invariant_a=FAIL`, `determinism=PASS`, `reconcile=PASS residual=-0.000000`, `randomwalk=PASS mean_pnl=0.2769 positive_seeds=10/20`, `signcheck=no_edge_either_way base_pnl=-0.9952 inverted_pnl=-0.1016`, `risk=PASS loss_p95_pct=0.311`).
2. `gap_invariants.py` always exits 0 regardless of `invariant_a=FAIL` — confirmed by design (its RESULT line reports the verdict; the process return code isn't used as a pass/fail signal). `run_all.py`'s failure count is therefore only sensitive to script *crashes*, not to substantive FAIL verdicts inside a script's own RESULT line. Is this the intended contract for future `gap_*` scripts, or should invariant/defect FAILs also set a nonzero exit code so `run_all.py`'s exit-code-as-failure-count design catches them?
3. Defect #2 (shorts not charged funding) needs the actual Bybit perpetual funding sign convention confirmed before a fix is written — the proposed fix in the defect table names both possible sign conventions rather than asserting one, since this audit's scope was measurement, not repair.
4. Defect #5 (notional vs. risk-based sizing) is a naming/behavior split that predates this audit (`position_size_pct` is documented as "risk per trade" in `backtest_engine.py:169` but implemented as a notional cap at `:401-402`). Should the fix be a rename (cheap, avoids re-baselining) or a behavior change to true risk-based sizing (changes every trade's position size and thus every historical P&L figure)? This decision affects re-baselining cost significantly and should be made explicitly, not as a side effect of a "risk" defect fix.
