## 2. Purging and embargo logic

For each test sample at index `t`, its label spans `[t, t + label_horizon)`. A training sample at index `s` is purged when its label window `[s, s + label_horizon)` overlaps the test window — i.e. `|s - t| < label_horizon`.

In group form, given a contiguous test group `[a, b)`:
- **Purge:** drop train index `s` where `s + label_horizon > a` AND `s < b + label_horizon`. Equivalently, exclude `[a - label_horizon + 1, b + label_horizon - 1]` from train.
- **Embargo:** additionally drop the next `ceil(embargo_pct * n_samples)` indices after `b`. Guards against serial-correlation leak when test bars influence the immediate-future training distribution beyond the label window itself.

Implemented as a single boolean mask per fold: `np.zeros(n, bool)`, set test groups to True, dilate by `label_horizon` (purge) and by `embargo_len` on the right side only (embargo), then `train_idx = np.where(~mask & ~test_mask)[0]`.

For the GRU case in `ml-retraining-service/app/core/model_trainer.py`, `label_horizon` should be passed as `prediction_horizon` (currently 5). If the input window itself leaks (sequence runs back `sequence_length=60` bars), the conservative effective horizon is `sequence_length + prediction_horizon - 1 = 64`. Expose `label_horizon` as a parameter and document this — different models may have different leak surfaces.

## 3. Combinations math and N/k defaults

`n_paths = math.comb(N, k)`. With `N=10, k=2` → 45 paths. Each bar appears in test exactly `C(N-1, k-1) = 9` times → 9 forecasts per bar.

**Tradeoffs (document in module docstring):**
- Larger `N` → more paths (better Sharpe distribution) but smaller groups → higher per-fold Sharpe variance.
- Larger `k` → coarser test sets but fewer paths. `k=2` is López de Prado's default. `k=1` collapses to k-fold; `k>3` yields too few paths to fit a distribution.
- Default `N=10, k=2` for crypto bar data is reasonable; expose as constructor args.

The harness **must validate** `n_samples >= n_groups * (label_horizon + embargo_len + 1)` and raise `ValueError` with concrete numbers when violated — silent degenerate folds are the worst failure mode.

## 4. Integration with ml-retraining-service

**Recommendation: evaluation-time CPCV, not training-time.**

Run CPCV on already-computed predictions, not by retraining the GRU N×C(N,k) times.

**Why:** 45 GRU retrains per symbol × 5 validated symbols = 225 retrains. Given the BTC OOM history flagged in `CLAUDE.md` gotchas, this is operationally hostile. Training-time CPCV is the textbook recipe but the lighter-weight alternative is well-defended (Bailey, Borwein, López de Prado, Zhu 2017, "The Probability of Backtest Overfitting") — apply CPCV folds *to the predicted vs. realised return series* without retraining.

**Bridge:** ml-retraining-service already produces `y_pred` via `_calculate_metrics` (`model_trainer.py:332`). After training, persist `(y_pred, y_true, timestamps)` to the model artifact alongside weights. risk-metrics-service loads that, derives strategy returns (sign of prediction × realised return), and feeds the array plus `prediction_horizon` into `CombinatorialPurgedCV.split(...)`.

**Tradeoff to flag in docstring:** evaluation-time CPCV detects out-of-sample Sharpe variability and selection bias, but does **not** detect training-set leakage — the GRU has already trained on the full series. To use CPCV's leakage-detection power fully, retrain per fold. Recommend evaluation-time as default; expose a `train_eval_callback` parameter for full retraining when compute permits (e.g., nightly cron, not every retrain).

## 5. Test strategy

Mirror `test_sharpe_metrics.py` style:

1. **Combinatorics:** `n_paths == math.comb(N, k)`; iterating `split()` yields exactly that many `CPCVSplit` objects with unique `path_id` and unique `test_groups`.
2. **Fold coverage:** every bar index in `[label_horizon, n - label_horizon)` (the purge-safe interior) appears in `test_idx` exactly `C(N-1, k-1)` times. Boundary bars near 0/n may be purged from all folds — fine if documented.
3. **Purge correctness:** for every fold, `min(|s - t|) >= label_horizon` for all `s ∈ train_idx, t ∈ test_idx`. Algebraic check.
4. **Embargo correctness:** for `embargo_pct=0.05, n=1000`, no train index lies in `[max(test_group_end), max(test_group_end) + 50)`.
5. **Leakage-detection oracle (load-bearing):** synthetic data where `y[t] = x[t + label_horizon]` (perfect future-leak target). Naive KFold scores R²≈1; CPCV with correct purging must score the predictor's actual generalisation (≈0 for an identity-leak model that only memorises training).
6. **DSR bridge:** `cpcv_to_dsr` with synthetic zero-mean returns across paths returns DSR near 0.5 and well below 0.95 (the pass threshold documented at `sharpe_metrics.py:235`).
7. **scipy cross-check (optional, gated like `test_sharpe_metrics.py`):** when scipy installed, compare C(N,k) iteration against `itertools.combinations`.

## 6. Risks

- **Small-sample failure:** with hourly SOL/BNB/ADA bars over a few months, `n_samples` may be only a few thousand. With `N=10, k=2, label_horizon=5, embargo=1%`, ~10–15% of samples are purged per fold — acceptable, but at <2000 samples a single fold's Sharpe estimator has wide CIs, and *variance across paths* will dominate DSR's `trial_sharpes_variance` term, not real disagreement. Plan: log per-fold sample counts; warn when `min(n_test) < 100`.
- **Regime non-stationarity:** CPCV assumes folds are exchangeable. A regime shift between groups (e.g., the 2026-04-25 testnet→mainnet flip noted in `CLAUDE.md` gotchas) violates exchangeability — test-set Sharpe distributions become bimodal, not Gaussian. Mitigation: filter input data to one regime; document loudly.
- **Strong autocorrelation of returns:** violates the i.i.d. assumption underpinning the per-path Sharpe estimator (PSR's skew/kurt term partially corrects, but CPCV inherits the assumption). Plan: use `probabilistic_sharpe_ratio` per-path rather than naive mean/std Sharpe.
- **Embargo undersizing:** 1% default may be too small for hourly bars with strong AR(1). Make it configurable; document a heuristic ("embargo ≥ effective autocorrelation half-life of the residual return series").
- **Path independence claim is approximate:** paths share training data, so the C(N,k) Sharpes are *correlated* trials, not independent ones. DSR's `expected_max_sharpe_under_null` formula assumes independence. Document this and conservatively understate `num_trials` (e.g., effective sample size via `1 / (1 + 2·avg_pairwise_corr)`) — or accept the bias and note it.
