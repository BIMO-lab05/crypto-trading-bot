## Red flags carried over from prior audits / open

These are not new this week, but the pause does not erase them. List
here so resume-day operator can't pretend the slate is clean.

1. **No reproducible OOS Sharpe + DSR yet.** ADR-013 acceptance gates
   (OOS Sharpe / IS Sharpe > 0.6, OOS Sharpe > 1.0, OOS max DD < 30%,
   DSR > 0.95) are still aspirational. Until cleared, every claim of
   "edge" is a CAN'T TELL by default.
2. **GRU models 4+ months stale** (trained Dec 10, 2025) and gated off.
   Even when re-enabled, V0 directional metric had look-ahead leakage;
   post-fix scores are chance-level on log-returns. Don't unfreeze
   without DSR > 0.95 on returns target.
3. **Paper per-trade cap relaxed to 10%** under ADR-010 (vs. 2% LIVE).
   Cap restoration step on the pre-LIVE checklist; flagging here so it's
   not forgotten when activity resumes.
4. **Auto-trader override drift.** CLAUDE.md says
   `AUTO_TRADING_ENABLED=true` set 2026-05-05 in `.env`. Today's
   premarket probe could not find that key in `.env`. Either compose
   default (false) is in effect, or override moved. Either way the
   doc-vs-truth mismatch is itself a red flag — silent disarm hurts
   exactly when an operator thinks the bot is armed.
5. **TimescaleDB has mixed testnet/mainnet history pre-2026-04-25.**

## Recommendations

Numbered, grounded in the above, no fluff.

1. **Don't un-pause until ADR-013 harness lands.** A week without trades
   is fine — restarting without the walk-forward acceptance gate just
   restarts the same dishonest-edge problem.
2. **Resolve the EMERGENCY_STOP dir-vs-file confusion.** `rm -rf
   EMERGENCY_STOP` it, then `touch EMERGENCY_STOP` if pause must
   continue. Future un-pause via plain `rm` then.
3. **Reconcile the `AUTO_TRADING_ENABLED` doc/truth mismatch.** Either
   re-add to `.env` (if intent is armed) or strike the line from
   CLAUDE.md (if intent is disarmed under operator-controlled
   override).
4. **Wire a host-side audit runner.** This scheduled task lives in a
   sandbox that can't reach `localhost:8000` on the Windows host (same
   constraint that blocked today's premarket probe and last night's
   circuit-breaker probe). Three of three probes this week were
   filesystem-only. Move the audit to a local cron / Windows Task
   Scheduler job that runs inside WSL2, or stand up a tunnel /
   read-only public dashboard the cloud probe can hit. Otherwise this
   audit cannot ever produce a real Sharpe number, only stubs like
   this one.
5. **When trading does resume**, first audit covers the *forward-going*
   window only (skip the historical-with-testnet-flips contamination).
   Apply `is_mainnet=true` filter explicitly even if the API claims to
   handle it.
