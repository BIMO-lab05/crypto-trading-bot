# T1.2 Vol Parity — Forward Paper-Test Kickoff Runbook

**Status:** runbook only. The 7-day clock starts when an operator runs the steps below.
**Prereq:** Docker + the unified compose stack are reachable. (This file was
authored from a WSL distro without docker access; the ops actions live on
the host.)

## Goal

Empirically check whether enabling per-position vol parity (T1.2 chunk 3,
commit `201526e`) improves risk-adjusted returns vs. the existing fixed-cap
baseline. Pass criterion: PSR(rebuild) > PSR(baseline) on the same trade
period. Kill criterion: realized daily P&L worse than baseline by > 0.5σ
(per the 2% per-trade / 5% daily-loss caps that already cap downside).

## Pre-flight

1. Confirm trading-engine is in **paper** mode and you have a recent
   baseline run to compare against:
   ```bash
   docker compose -f docker-compose.unified.yml exec trading-engine \
     env | grep -E "PAPER_TRADING_MODE|TRADING_MODE|BYBIT_TESTNET"
   # expect: PAPER_TRADING_MODE=true, TRADING_MODE=PAPER, BYBIT_TESTNET=false
   ```
2. Capture baseline metrics (last 7 closed days) before flipping the flag,
   so the comparison has a control:
   ```bash
   curl -s http://localhost:8009/api/v1/portfolio/paper_trading/sharpe \
     | jq '{sharpe_ratio, sortino_ratio, total_return, volatility}'
   curl -s http://localhost:8005/api/v1/trades/history?limit=200 \
     | jq '[.trades[] | select(.status == "CLOSED")] | length' \
     > /tmp/baseline_closed_trades_count.txt
   ```
   Record the resulting numbers + the wall-clock timestamp in
   `progress.md` under the kickoff entry.

## Flip the flag

The vol-parity overlay is only T1.2; T1.3 maker-orders and T2.3 funding
gate stay off (LIVE-only).

Edit (do **not** commit) `services/trading-engine/.env`:
```
ENABLE_VOL_TARGETING=true
# defaults are fine, but spell them out so the operator can see what they're picking
VOL_TARGET_ANNUALISED=0.30
VOL_ESTIMATOR_WINDOW_BARS=168
VOL_TARGET_CAP_MULTIPLIER=1.0   # 1.0 = downside-only (safest)
```

Restart trading-engine to pick up the new config (stale in-memory state is
the most common false-pass — see CLAUDE.md `Verification standards`):
```bash
docker compose -f docker-compose.unified.yml restart trading-engine
docker compose -f docker-compose.unified.yml logs --tail=200 trading-engine \
  | grep -E "vol_target|VolEstimator|enable_vol_targeting"
# expect: a log line confirming enable_vol_targeting=True at startup,
# and the realized-vol estimator initialising on a trade tick.
```

## During the test

Don't change strategy parameters mid-run. The estimator needs ~168 hourly
bars (7 days) to be warm; the *first* day will fall back to baseline
sizing on most symbols, which is fine.

Monitor (cheap, run from host):
```bash
# Once a day:
curl -s http://localhost:8009/api/v1/portfolio/paper_trading/sharpe | jq
curl -s http://localhost:8005/api/v1/trading/status | jq '.kill_switch_active'
# Open positions + realised PnL roll-up:
curl -s http://localhost:8003/api/portfolio/paper_trading/performance | jq
```

If the kill switch trips, document the trigger in `progress.md`, then
disable vol targeting (`ENABLE_VOL_TARGETING=false`) before re-arming.

## Day-7 evaluation

Compare to the baseline you captured at kickoff. Apply Probabilistic
Sharpe Ratio honestly — both runs share the same period so PSR is the
right test:

```bash
# From the host. Both calls hit the risk-metrics service which now has
# the PSR/DSR module from T0.2 (commit `6ebebdc`).
curl -s "http://localhost:8009/api/v1/portfolio/paper_trading/probabilistic-sharpe?benchmark=0.0" | jq
```

Decision matrix:

| Outcome | Action |
|--|--|
| PSR(vol-parity) > PSR(baseline) at p < 0.10 | Promote: keep flag on, document in `docs/strategy/`. |
| PSR(vol-parity) ≈ PSR(baseline) (overlap) | Inconclusive. Run another 7 days OR enlarge `vol_target_cap_multiplier` to 1.5 and rerun. |
| PSR(vol-parity) < PSR(baseline) at p < 0.10 | Reject: flip flag off, write the negative result into `docs/strategy/research-2026-04-29/`, link the commit. |
