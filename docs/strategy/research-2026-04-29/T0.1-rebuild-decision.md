## Interpretation

This is the V0 finding compounded. V0 (commit `c56765c`) showed the
production GRU's marquee R²=0.99 was autocorrelation noise: persistence
matched it, log-returns scored coin-flip after the look-ahead bug fix.
The rebuild attempted three honest fixes simultaneously — target the
right thing (log-returns), drop level features, shrink the model — and
still found nothing. Hourly crypto returns at 1-bar horizon, with
this feature stack and this architecture, have no measurable edge.

That's not a failure of execution. It's an empirical fact about the
target.

## Why bigger nets / more features / more epochs won't help

- **R² on returns is *negative*.** A bigger model would just learn
  more noise. Negative test R² with tiny variance across CPCV paths is
  the signature of overfit-then-fail-OOS, not of an underfit model.
- **Dir-acc *below* 0.5 on SOL and BNB.** Random output would average
  0.5; the model is consistently picking wrong. More capacity only
  doubles down on whatever spurious pattern it's locked onto.
- **OOS Sharpe near zero with tight CI.** The CPCV path Sharpes
  (45 paths each) cluster around zero with std ~0.03–0.04. There is
  no signal to extract; bigger nets find more noise.
- **20 epochs with early stopping wasn't the limiting factor.**
  Training MAE flattened by epoch 10–15 in the logs. More training
  doesn't help when the target is unpredictable.

## What this closes

- T0.1 implementation chunks 1–5 are done.
- `ENABLE_ML_PREDICTIONS=false` (set in commit `2f29ca9`) **stays

## Recommendations for T0.1.x (deferred — not started)

If a future session wants to take another swing at the GRU side:

1. **Different horizon.** 1-bar log-returns are noisiest. Try 4-bar
   (4-hour) or 24-bar (1-day). Position turnover drops; signal-to-noise
   ratio rises. Caveat: changes the trading frequency assumption.
2. **Classification head (Form B from the design Q1).** Three-class
   {-1, 0, +1} with a flat-zone threshold may fit the actual betting
   structure better than regression on a heavy-tailed target. Adds
   plumbing work in `ml-prediction-service`.
3. **Non-DL control.** XGBoost on the same stationary feature stack is
   maybe a 2-hour build. If it equals the GRU (likely), the GRU
   complexity is decorative. If it beats the GRU, the GRU
   architecture is wrong — try transformer or TCN. Either way the
   answer is informative.
4. **Cross-sectional features.** All current inputs are per-symbol.
   BTC/ETH macro vol, total-market direction, sector momentum are
   proven crypto factors per the synthesis (research-2026-04-29 doc 1).
   Adding even one cross-sectional feature might materially change
   the fit.
5. **Sentiment as a filter, not a target.** The sentiment service is
   live (real news + social, no fabrication after `41bd5ab`). Use
   sentiment as a regime filter (skip trades when sentiment is
   strongly negative) rather than try to predict it.

These are hypotheses; none have evidence yet. The honest action today
is: ship this decision, leave ML off, focus on execution-side
improvements that have clearer downstream payoff.
